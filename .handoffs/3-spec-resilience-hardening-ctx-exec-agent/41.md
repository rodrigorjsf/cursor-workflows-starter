## What was built
Test-only change; no product code touched (the Agent Brief settled that the command runner and the engine are right).
- "cancelling the run kills the running commands..." (`exec.test.ts`) no longer fails when a killed `sleep` is still an unreaped zombie. `alive()` now reads the state from `/proc/<pid>/stat` and treats `Z`/`X` as not running; the test waits (3 s bound) for the grandchildren to be gone instead of reading them once. A process that is really left running still fails it.
- "schema re-prompts share the step timeout instead of restarting it" (`cancel.test.ts`) no longer depends on a 150 ms margin: 2000 ms step timeout, 1000 ms first send. The end-time bound comes from the re-prompt's own start (`stepTimeoutMs + 0.75 * beforeReprompt`), not from `durationMs < 600`. A re-prompt that gets a fresh full timeout still fails it.
- New deterministic test for `alive()` with a real zombie, so the helper is covered without needing load.

## Decisions & deviations
- **Poll on every platform, not only without `/proc`.** The brief says to poll `kill(pid, 0)` where there is no `/proc`. I use one path: `expectGone()` polls `!alive(pid)` for up to 3 s everywhere, with `alive()` zombie-aware where `/proc` exists. One code path, same bound as the file's two existing "left behind" tests, and it covers the short window in a dying process between closing its pipes and becoming `Z`. A process really left running still fails (mutation above). Recorded because it is looser than "check once" on Linux.
- **`expectGone()` extracted and used by two other tests** (lines for "a process the command left running..." and "the whole process tree is killed...") that had the same `until` + SIGKILL + `assert.fail` block; adding a third copy would be duplication. Same behaviour, except a zombie now counts as gone there too.
- **Test 2 margins:** the first send ends 1 s before the timeout fires; the step may end up to 0.75 s late (`beforeReprompt * 0.75`) before it is taken for a restart. Detection margin on a real restart is ~250 ms over a few ms of jitter (mutation: 3028 ms vs a 2750 ms line). I did not use a promise controlled by the test: the engine's timer is a wall-clock timer, so any scheme needs a real delay between the step start and the re-prompt; wide margins are the simplest.
- The zombie in the new helper test is made deterministic by killing the child only after its parent shell has `exec`'d into `sleep` (a running shell reaps its children, so a child that died before the `exec` leaves no zombie).
- No CHANGELOG or docs change: test-only.

## Learnings
- A fresh worktree has no `node_modules`: `mise exec node@22.23.4 -- npm ci`, then prefix every command with `mise exec node@22.23.4 --`.
- Reproduce "fails 1 in 3 under load" with 16 `timeout 900 sh -c 'while :; do :; done'` started via `setsid` and their pids recorded in a file (kill by pid, not by `pkill -f`); a pass proves nothing without the load.
- A deterministic zombie for a test: `bash -c 'sleep 60 & echo $!; exec sleep 30'`, wait until the parent's `/proc/<pid>/comm` is `sleep`, then SIGKILL the child.
- Hung `sleep 60/61` children of a failed run: `kill <pid>` by pid; `pkill -x sleep` also hits other sessions' sleeps.
