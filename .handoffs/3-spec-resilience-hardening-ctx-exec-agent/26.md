## What was built
- **Tier from the highest label.** With `complexity:low` and `complexity:high` on one issue the tier is HIGH, in any label order (before: the first label that matched). A label named like an `Object.prototype` member (`constructor`) is only a label now.
- **A crash loop stops.** A resume that finds a write step still marked in flight adds one crash to that step (`progress.crashes[stepId]`). Past `maxStepCrashes` (default 2) the run ends with `status: "step-crash-loop"` (`step`, `crashes`, `limit`, `worktree`, `hint`) instead of running the step again. The count stays in the progress, so the next resume stops too; raising the limit in the config lets the step run. A cancel in the middle of the step is not a crash.
- **A retry starts clean.** New `agent()` option `revertOnRetry` (opt-in): before each retry of a write step the engine puts `cwd` back to the snapshot it took at the start of the step. `implement-issue`'s `writeStep` turns it on. The failed attempt's `step-end` says `reverted: true`.
- **Limits are config.** New generic `meta.settings` (code defaults) / `ctx.settings` / `workflows.<name>.settings` (global then repo file). `implement-issue` declares seven: `sliceCaps`, `extraSlices`, `fixRounds`, `redGreenAttempts`, `maxDiffChars`, `labelTiers`, `maxStepCrashes`. The schema validates them, `run-start` and `wf config show` print them with their origin, and `docs/reference/config.md` documents them (regenerated).

## Decisions & deviations
- **Settings are a generic mechanism, nested under `settings`**, not flat fields of `workflowPrefs` like `execTimeoutMs`. The workflow owns names and defaults (`meta.settings`), the resolver rejects a name it did not declare (same as roles), the schema validates and documents the kit's own seven (`workflowSettings` definition, `additionalProperties: true` so a repo's own workflow can declare other names; the kit does not type-check those). Settings live in a map apart from the resolver's `cells`: those rules (caps, chat overrides) go by the last pointer segment, and a setting named `maxTokens` must not meet them (tested). Layers: code < global < repo only; no env var, flag or chat override (ADR-0001 amended). Each setting is one value: a higher layer replaces the lower one whole (`labelTiers` replaces the default map; `sliceCaps` needs all three tiers).
- **Seventh setting `maxStepCrashes`.** AC2 says "a configured number" but the AC4 list has six; the crash limit is configured like the others (default 2: a step may crash the process twice and be resumed; the third crash stops it).
- **`revertOnRetry` is an engine option, opt-in.** The engine owns the retry loop (`retries`), and the config can override `retries` per role, so a workflow-level retry loop could not guarantee it. Default off because the undo restores the whole directory: two parallel writers in one directory would lose each other's files. The spec lists it under `implement-issue` changes; implement-issue is the only user. On a directory that is not a git repository the retry runs anyway with a `warning` (same as cancel).
- **`step-crash-loop` is returned, not thrown**, like the workflow's other failure statuses; the interrupted step is undone first so the worktree is clean for inspection. It is not in `PENDING` (a failure).
- **Timeouts not moved to config.** `networkTimeoutSec` (arg), `LOCAL_GIT_TIMEOUT_MS` and `testTimeoutSec` stay as #24 left them; no AC asks for them.
- The old `InFlight.resumes` field (never read) was replaced by `interrupted?` and `Progress.crashes`; old progress files with `resumes` still load.
- Docs touched: CHANGELOG, `docs/reference/config.md` and `events.md` (regenerated), `docs/authoring/01-escrevendo-workflows.md`, `docs/internals/01-arquitetura.md`, ADR-0001, both skill copies of `runtime-api.md` and `recipes.md` (identical), header comments of `implement-issue.ts` and `worktree-snapshot.ts`.

## Learnings
- The worktree has no `node_modules`: `mise exec node@22.23.4 -- npm ci`, then prefix every command with `mise exec node@22.23.4 --`.
- `gh issue view N --comments` prints nothing through the RTK rewrite; `gh issue view N --json title,body,comments` works (same as #22 and #24; the global RTK deny-list edit was not done, outside the worktree).
- The shared machine is often at load 17 to 27: a single red full run is not a verdict. Rerun the failing file alone, and on the base commit extracted with `git archive <sha> | tar -x -C <dir>` plus a `node_modules` symlink, before blaming the change.
- `git read-tree --reset -u` does not remove untracked files: pair it with `git clean -fdq` when "put the tree back" must be exact.
- Busy loops started for a load probe (`timeout 100 sh -c 'while :; do :; done'`) outlive the command that started them: kill them by name afterwards (`pkill -x timeout`), never `pkill -f`.
