## Decisions & deviations
- Layout: the proofs are a second script (`prove-gitlab.ts`) run by `gitlab-e2e.sh` after the recorder, not part of the recorder: the recorder writes committed fixtures, the prover prints evidence and spends tokens. The recorder's inline `GitLabApi`, `git`, `exec`, glab login moved to `scripts/lib/gitlab-e2e.ts` so both share them (behaviour unchanged; the existing tests stayed green).
- Order and cost: the three free proofs run before the one that spends tokens. `GITLAB_E2E_STAGES=closing,quick-actions,references` skips the paid one. Caps `GITLAB_E2E_MAX_TOKENS` (600000) and `GITLAB_E2E_MAX_CENTS` (100) are passed to `wf run` as `--max-tokens` and `--max-cents` (the repo rule); a LOW run measured 236 to 307 thousand tokens. `GITLAB_E2E_WORKFLOW_TIMEOUT_SECONDS` (2700) cancels a hung run.
- The real run is isolated: `WF_HOME` in the scratch dir with `{"forges": {"localhost:8929": "gitlab"}}`, `WF_METRICS=off`, `GLAB_CONFIG_DIR` and `GIT_CONFIG_GLOBAL` in the scratch dir (token as `http.<url>.extraHeader` there, never in a repo config), the Cursor login from the real `HOME` (`wf login` must be done). The user's `~/.config/glab-cli`, git config and metrics DB are not touched.
- Surfaces for `/close`: an issue note (the path of the seams comment) and an MR description. No MR note: `Forge` has no MR-comment method, so the workflow never writes one. A `/close` in an MR description closes the MR (not the issue): the verdict checks the MR state there, and the issue state for a note.
- A "no effect" counts only beside a control that took effect (`Closes #N` closes, a bare `/close` runs on both surfaces, the raw references link and cross-reference). I did not require every payload to fire raw: GitLab 19.5.5 itself does not run `/close` followed by a tab, after `<div>` or `>>>`, or in tilde and four-backtick fences, and a script that failed on that would fail for a good reason. The evidence shows raw and sanitized side by side and says how many ran as written (6 of 12).
- Payloads: the ticket's list, plus a CRLF case. The "lone `\r`" case is `Done.\n\r/close` (GitLab drops `\r` before looking for a command, so `Done.\r/close` is never a command: the first draft proved nothing). The never-closed fence case is a left-open fence in one piece followed by a fenced `/close` in the next (the shape where the parity flip puts `/close` outside code: raw it runs, after the guard it does not).
- Phrases: all 16 words of GitLab's default pattern plus six shapes (`CLOSES`, `Closes:`, `Fixes issue #N`, `group/project#N`, issue URL, in a sentence): the sanitizer claims them, so the real instance is asked about them. Only `CLOSES #N` (all capitals) never closes: GitLab's pattern accepts only `Close`/`close` style first letters.
- The merge waits for the MR's `prepared_at`: GitLab records which issues an MR closes in a task that runs seconds after the MR opens, and a merge before that closes nothing (measured: `Fixes #N` merged 2.6 s after opening left its issue open, twice in a row on different phrases). A person merges later, so this affects only the proof, not users.
- Project `owner/proof` is refused when it exists (scripts are safe to run twice by refusing); against the throwaway GitLab it never does.
- The final run re-recorded `packages/runtime/test/fixtures/glab/recordings.json` (only ids and timestamps differed); I restored the committed file with `git restore`: the fixtures are not part of this ticket.
- Docs: pt-BR rows in `docs/contributing/04-scripts-do-mantenedor.md` (updated `gitlab-e2e.sh` row, new `prove-gitlab.ts` row), `scripts/verify/README.md` (section and variable table), and a `CHANGELOG.md` bullet under "Adicionado". ## Learnings
- GitLab records which issues an MR closes in a task after the MR opens (`prepared_at` on the MR); merging earlier closes nothing. Wait for `prepared_at` before merging in any script.
- GitLab's default closing pattern is case-sensitive on the first letter only: `Closes #N` and `closes #N` close, `CLOSES #N` does not. `Implement`, `Implements`, `Implemented` and `Implementing` do close.
- On GitLab 19.5.5, `/close` runs after `\r`, with CRLF, after `$$`, and after a fence a previous piece left open; it does not run followed by a tab, after `<div>` or `>>>`, or inside tilde, four-backtick or three-backtick fences. The guard is stricter than GitLab on purpose (older versions match with a regex).
- A deleted GitLab project is renamed `<name>-deletion_scheduled-<id>` and its old path redirects (a `fetch` follows it and "finds" it): remove for good with `DELETE /projects/:id?permanently_remove=true&full_path=<url-encoded full path>`.
- In a bash script, `trap cleanup EXIT INT TERM HUP` with `local status=$?` gives the status of the last command (0 after a `sleep`), so a signal reads as success: pass `128+n` per signal.
- Never edit a bash script while it runs: bash reads it by byte offset, and an edit above `main "$@"` makes it read the tail of the new file when `main` returns.
- `fetch` throws "Request with GET/HEAD method cannot have body": a test that sends a body must POST.
- `mise` in a fresh worktree: `MISE_TRUSTED_CONFIG_PATHS=<worktree> mise exec -- …` (no persistent `mise trust`).
- `wf run` prints the outcome JSON on stdout and its event stream on stderr; Node's `ExperimentalWarning: SQLite` goes to stderr too.
