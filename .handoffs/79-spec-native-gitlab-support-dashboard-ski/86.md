## What was built
The dashboard Board shows open, merged or closed for a card link that is a GitLab merge request, on gitlab.com and on every host
named in glab's `config.yml`. The state comes through the runtime's `observe` entry point: a new `prStateOfUrl(url, signal)`
(`packages/runtime/src/runtime/pr-by-url.ts`) runs `glab api --hostname <host> projects/<enc path>/merge_requests/<n>` (never
`glab mr view <url>`). GitHub goes through the same entry point with the same `gh pr view <url> --json state --jq .state` line
it had before, so `packages/dashboard/src/pr-state.ts` now keeps only the cache, the queue and the abort. A URL that is not
exactly a PR or MR address, or whose host is not allowed (github.com, gitlab.com, glab's config hosts), gets no state and starts
no process. Only host names are read from glab's config, and nothing is logged.

## Decisions & deviations
- **Hosts come from reading glab's `config.yml`, not from a glab command.** The spec says "prefer a glab subcommand that lists hosts if one exists". The only one is `glab auth status --all` (`--output json` in 1.130): its source (`internal/commands/auth/status/status.go` at v1.130.0) calls the API of every host with a 30 s timeout, host after host, so one dead host would hold back every badge, and it contacts every instance on each refresh. Reasoning is written in `pr-by-url.ts`.
- **Config lookup:** `GLAB_CONFIG_DIR` alone when set, else `~/.config/glab-cli/config.yml`, else `$XDG_CONFIG_HOME/glab-cli/config.yml` (glab's `config_file.go` order). macOS (`~/Library/Application Support`) and Windows defaults are not read; the kit is tested on Linux only (`docs/usage/01-instalacao.md`), and `GLAB_CONFIG_DIR` set for both glab and the dashboard covers them. Recorded in the code comment; no issue filed (platform not supported by the kit).
- **No YAML parser:** host names are the bare keys exactly one level below the top-level `hosts:`; a key must also match the host pattern. Read afresh on every ask (a host the user logs in to later gets badges after the failure TTL, tested).
- **GitHub moved into the runtime too** (ADR-0009: "the observe entry point exports only the state of a PR by URL"). Same argv; `maxBuffer` is now 4 MiB for both CLIs (`glab api` prints the whole MR).
- **URL strictness:** GitHub regex unchanged. GitLab: `https` only, lower-case host (optional port), at least two namespace segments each starting with `\w`, `/-/merge_requests/<1..9 digits>`, no suffix. A GitLab-shaped URL on github.com is none, even if glab's config lists github.com. `locked` maps to open.
- **Env:** `NO_PROMPT=1`, `GLAB_CHECK_UPDATE=false`, `NO_COLOR=1` for glab; the previous three variables for gh. The rest of `process.env` passes through (glab needs `GITLAB_TOKEN`/config to authenticate).
- The `mise.toml` pin of glab, the Docker script and fixtures, and the version bump are #88/#89/#90 and untouched.
- `CODING_STANDARDS.md` Security bullet "Treat a URL from run data as untrusted" rewritten for both forges, its `_See:_` now `pr-by-url.ts:37` (a test checks the cited line is not blank: re-check it if the file shifts).
