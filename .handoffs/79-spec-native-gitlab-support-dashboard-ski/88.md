## What was built
- `glab` 1.130.0 is pinned in `mise.toml`.
- `scripts/verify/gitlab-e2e.sh`: one opt-in command. It starts `gitlab/gitlab-ce:19.5.5-ce.0` (override: `GITLAB_E2E_IMAGE`) in
  memory-constrained mode (one Puma process, Sidekiq 5, Prometheus off, `--shm-size 256m`, published on 127.0.0.1 only), waits for the
  health check and the sign-in page, reads the root password from the container, makes a personal access token inside it, runs the
  recorder, and removes its container and its three volumes on success, on failure and on a signal. It never restarts or configures Docker.
- `scripts/verify/record-glab-fixtures.ts`: makes group `owner`, project `repo`, two issues and a branch on that GitLab, then drives the
  runtime's own `GitlabForge` (through a wrapper `glab` on the PATH that tees every call) plus the doctor's `glab auth status` check, so
  the recorded commands are exactly the runtime's. Writes the scrubbed outputs to
  `packages/runtime/test/fixtures/glab/recordings.json` (10 recordings).
- The fake `glab` of the offline tests (`fakeGlab` in `packages/runtime/test/implement-issue.fixture.ts`) now plays those recordings: each
  object is the recorded one with the test's fields set on it. `doctor.process.test.ts` plays the recorded `auth status` answers.
- The script was run for real twice against GitLab CE 19.5.5 (exit 0, no container, volume or scratch dir left behind).

## Decisions & deviations
- Name and layout: script in `scripts/verify/` (next to the other real-world checks); recorder is a second script; the pure scrubbing is `scripts/lib/scrub-recording.ts`. Ticket #89 extends the same script with its proofs.
- The recorder reuses the runtime's `createForge("gitlab", Commands)` instead of a hand-kept list of argument vectors, so a changed command is re-recorded, not forgotten. A wrapper `glab` captures each call (stdin forwarded).
- One `recordings.json` (args, exit code, stdout, stderr per recording, plus `recordedWith`, `subjects`, `placeholders`) rather than a file per stream.
- The recorded host is the placeholder `gitlab.example.com`; URL schemes stay as glab printed them (`http://`). The fake and `recorded()` map it to `https://gitlab.com`.
- The group is `owner` and the project `repo`, so recorded paths already match the fake's `owner/repo`.
- Docker memory floor 4096 MiB (`GITLAB_E2E_MIN_MEMORY_MB`): the user's WSL has a history of VM crashes; the script refuses early rather than thrashing.
- Mid-run I used a dev container named `wf-e2e-88-dev` to iterate on the recorder; it and its volumes were removed before the final full-script runs.
- Edited `CHANGELOG.md` (a pt-BR "Adicionado" bullet), the 9.4 table, `scripts/verify/README.md` and the `scripts/lib/cli.ts` header: the repo's script conventions and doc tests require them. No `CLAUDE.md`/`AGENTS.md` edit.
- Left in Docker: the pulled image `gitlab/gitlab-ce:19.5.5-ce.0` (6.1 GB), so the next run does not pull again. `docker rmi` removes it.

## Learnings
- GitLab CE reports Docker health `healthy` minutes before nginx and Puma answer: wait for the sign-in page too.
- `glab api --paginate` joins pages into one JSON array; GitLab lists notes newest first.
- `glab mr create` prints only the URL on stdout; its text and a CE-only "target branch rules 404" warning go to stderr.
- A project's REST JSON carries `runners_token`; scrub with the runtime redactor, not a prefix list.
- `NO_PROMPT` is deprecated in glab 1.130 and warns on stderr; do not set it.
- A backtick in a comment inside the fixture's template-string fake breaks every test file that imports the fixture; tests are not typechecked, so only the test run shows it.
- Doctor's `saidBy` shows glab's boxed `ERROR` header line first (real output); harmless, left as is.
