## What was built
A workflow author or a new user reading the skills, the book or the README now learns that GitHub (`gh`) and GitLab
(`glab`) are both supported, that the host of `origin` picks the forge and a self-managed host goes under the `forges`
key, and that a GitLab cloud step rests on Cursor's own support, which the kit does not validate.

- Both authoring skills got a "Forge commands" table (read an issue, comment, open a PR, find a branch's PR) with `gh`
  and `glab` side by side, in `references/runtime-api.md`, plus `glab` in rules 6 and 8 and a fake `glab` and a throwaway
  GitLab project in `references/testing.md`. The pt-BR twin of the table is in the authoring chapter (4.1).
- README (both languages), install guide, installation, invocation, observability, authoring, governance and
  architecture chapters name both CLIs; install, README and authoring name the `forges` key.
- `docs/reference/config.md` is regenerated: `networkTimeoutSec` covers `glab`, and the cloud section carries the GitLab caveat.
- New `test/forge-docs.test.ts` keeps `gh` from being taught alone.
