## What was built
A role can be configured to run on a Cursor cloud agent: `workflows.<name>.roles.<role>.location` (`local` default, or `cloud`) in either config file. It is honoured only when the global file's `caps.allowedLocations` allows `cloud` (absent key = local only; a request the cap refuses runs local and is recorded as a violation) and the workflow declares the role `ok` or `read-only` (`never` is rejected before the run). A read-only step then runs on a cloud agent: the engine's cloud backend pushes a throwaway branch `wf/cloud-snapshot/<run>/<id>` holding the worktree as it is on disk (uncommitted and untracked files included, nothing staged or moved locally) to `cloud.remote` (default `origin`), creates the agent with the SDK's `cloud` options (never tools, allowlists, system prompt or setting sources), warns that setting sources are ignored, deletes the branch when the attempt ends, and validates a structured result from the answer's final fenced `json` block with Ajv, re-prompting in the same conversation within `schemaRetries`. Memo is skipped, and tokens and cost come from the cloud agent's usage and count against the caps.

## Decisions & deviations
1. **"Read-only role to cloud write" is checked by the engine, not the resolver.** Whether a step writes is its `tools` (known only at the `agent()` call), so the resolver rejects a `never` role (and any `location` on a label) and `runStep` rejects, before the first attempt, a cloud step that can write: role-declared `read-only` gets a message naming the declaration; an `ok` role gets "a step that can write cannot run in the cloud yet". ADR-0005 amended to say so.
2. **`allowedLocations` defaults to `["local"]` when the key is absent** (explicit `null` still allows every location). Spec: "defaults to local only"; story 2. Changes the effective caps recorded in `run-start` for runs with no such key (3 existing assertions updated).
3. **`cloud.remote` is a top-level preference** (`cloud: { remote }`, valid in both files, repo wins, default `origin`, name pattern forbids a leading dash), recorded in the effective config with provenance.
4. **Snapshot per attempt, inside the cloud backend** (not in the engine), so the engine stays location-agnostic; branch name `wf/cloud-snapshot/<sanitized run id>/<8 hex>`; built from a temp copy of the index with `git add -A` (excluding `**/.workflows/**`), `commit-tree` parented on HEAD, pushed with `--no-verify`.
5. **Backend selection:** `RunOptions.backend` serves the steps of its own `location`; the other location uses its default (local SDK agents, or the lazily created cloud backend).
6. **Events:** `location` added (optional) to `step-start` and `step-end` (spec story 17); effective config gains `roles.<r>.location` (default `local`, with provenance) and `cloud.remote`.
7. **Cloud steps get no nested-workflow guard MCP server** (it is a command of this machine, which a VM cannot run, and the VM cannot reach this machine's `workflows` server either).
8. **Extraction is lenient on purpose:** last complete fenced block labelled `json` or unlabelled, trailing prose allowed; the schema is the guard.
9. **`AgentBackend` seam:** new `warning` attempt event (the engine must not treat it as "the agent exists") and `StepOptions.writes`; `runAttempt`/`converse` extracted from the local backend so both backends share abort, cancel, usage and re-prompt rules (local behaviour unchanged: the existing 520 tests passed untouched).
10. Read-only cloud prompt: since the allowlist cannot be sent, the prompt says the step is read-only.

## Learnings
- A fresh worktree has no `node_modules`: `mise exec node@22.23.4 -- npm ci --prefer-offline` takes about 3 s.
- Edit `config.schema.json` by text replacement: `json.dump` reformats the whole file (a 360-line diff).
- A backend's non-agent events (a warning before the agent exists) must not reach `AttemptAbort.agentReady()`, or a held-back token cap aborts a creation in flight.
- Git ref components reject `..`, a trailing `.` and `.lock`: sanitize any caller-supplied id before it goes into a branch name.
