## What was built
Seven runtime hardening items and four extra criteria, each test-first.
- **Job cap.** `caps.maxRunningJobs` (global file, default 3, `null` lifts it). `wf start`, `start_workflow` and the dashboard's Start refuse a job when that many run in the repository, and refuse a job that runs the same workflow with the same args as a running one. Refusal happens before any job record or process exists (`start_workflow` answers `isError`).
- **Scrubbed environment.** `ExecOptions.scrubSecrets`: the test suite and the `setupCommand` run without `KEY`/`TOKEN`/`SECRET`/`PASSWORD` variables (`CURSOR_API_KEY`, `GH_TOKEN`); the workflow's own `git`/`gh` calls keep their tokens.
- **Snapshot guard.** A cloud snapshot that differs from HEAD is scanned for secrets (always) and its remote is asked `gh repo view <url> --json visibility`; PUBLIC, or gh unable to answer, is refused (final for the step) unless the global-only `cloud.allowPublicRemote` is true. `--no-verify` stays, with its reason in a comment.
- **Repo code listing.** `wf doctor`'s `config` check warns and lists the hook commands (`.cursor/hooks.json`, `.claude/settings.json`) and MCP server commands (`.cursor/mcp.json`, the kit's `workflows` server excluded) when a step can load `"project"`; the run emits one `warning` with the same list before its first step.
- **`wf init`** refuses (exit 1, naming the file) any file whose real path, or whose folder's, is outside the repository, before reading or writing; in-repo links still work.
- **Model links.** `sanitizeModelText` shows an image, link, HTML tag or bare URL pointing outside the forge as inline code with the scheme broken by a zero-width space.
- **Dashboard.** Both entries mount in an `ErrorBoundary` with `onUncaughtError`; the Run view drops stream messages that are not events (with a console warning).
- Extras: read-only cloud step that pushes gets a `warning` naming the branch; AST check that no workflow runs `git push` itself; the run store redacts the key `wf login` saved; SECURITY.md, book, skills, ADRs, CHANGELOG updated.

## Decisions & deviations
- **`spawnJob` takes the cap** (`maxRunningJobs: number | null`, required) so no door can forget it; the dashboard's Start (`run-start.ts`) gets it too, mapped to its existing `refused` outcome (409). The MCP handler now spawns before it starts the dashboard, so a refused call starts neither.
- **Duplicate rule needs the workflow name**: `JobStart` gained `workflow` (ADR-0008 amended). Four existing assertions on `start` now include it. Older records without it are never seen as duplicates.
- **Cross-process race is a known limit**: the check and the record write are synchronous in one process, but two processes can both pass (documented in SECURITY.md and `jobRefusal`'s comment). A lock would need a synchronous wait in the MCP server's event loop; I judged a rate limit enough for the threat (one looping agent).
- **`scrubSecrets` is a boolean on `ExecOptions`** (the ticket says "an env policy"); the explicit `env` of a call is kept even when secret-named.
- **Held job in the tests** is a repo workflow with a `[fake:hang]` step started by the real `wf start`, not `hold-run.ts` (that one runs `runWorkflow` in-process, not as a job, so it cannot count as a running job).
- **Visibility check**: `gh repo view <the URL the agent is given>` (a remote named other than `origin` is the one asked about); INTERNAL counts as not public; it runs only when the snapshot differs from HEAD, and the secret scan always runs, `allowPublicRemote` included. GitLab remotes (the `glab` is not asked) are refused unless opted in: ADR-0009 and ADR-0007 amended. The check lives in `src/runtime/remote-visibility.ts`, the one place in `src/` that names `gh`.
- **`cloud.allowPublicRemote`** is in `cloudPrefs`; a repo-file value is a config violation (`/cloud/allowPublicRemote`), like `dashboard`. No provenance cell (global-only, like `caps`).
- **Doctor**: no tenth check id; the warning rides the existing `config` check. The run warning is computed from the effective config (`loadsProjectSettings`) plus the three files.
- **Read-only cloud push**: a `warning` event (the ticket allows fail or warn), not a failure: the push is already done and the step's answer is still its answer. The fake SDK now reports a pushed branch only for an agent that works on the current branch (a read-only agent pushes nothing unless a script says so). What the real API reports for a read-only agent that made no commit is unmeasured: if it lists a branch, the warning would be noise (#47 measures it).
- **Link neutralization goes beyond a plain code span**: the scheme is broken with a zero-width space inside the span, because a backtick the model writes next to the link would otherwise pair with the added span and leave the link live (a bypass found by analysis). After review it also reads links as the parser does (character references, backslash escapes, tabs in the scheme, balanced parentheses) and treats `www.` autolinks. The forge's own host stays clickable (`github.com`; `gitlab.com` for GitLab). Links to a self-managed GitLab host are shown as code. The closing-keyword test for a `gitlab.example.com` issue URL now expects the scheme-broken form.
- **Dashboard**: `crash.css` is imported by the two entries (a Node test cannot load a style); the class component needed a one-line change to the `badExports` check in `test/coding-standards.test.ts` (an exported class counts). The plain-DOM `onUncaughtError` path is not verified in a browser (the chrome-devtools MCP did not connect): filed as #101.
- Message of the secret guard: rule strings now say "in the change" instead of "in the commit", since a snapshot has no commit yet.
- No `CLAUDE.md` or `AGENTS.md` edited.

## Learnings
- A fake `gh`/executable placed under `packages/` is an ES module (the package has `"type": "module"`): use `process.getBuiltinModule("node:fs")`, not `require`, so it runs there and in the system's temp folder.
- gitleaks flags `KEY: "high-entropy literal"` in a test: build fake secrets at run time (`"x".repeat(24)`), no allowlist.
- The dashboard palette test reads `#101` in a comment as a hex colour: name an issue by its URL in dashboard sources.
- `repoWithRemote` (cloud tests) now installs a PRIVATE fake `gh` on the PATH; a test that needs another answer calls `fakeVisibilityGh(dir, answer)` after it.
- Adding a field to the job record's `start` breaks exact `deepEqual` assertions in four process tests: grep `\.start,` before changing `JobStart`.
- `npm run check` stops after the first failing workspace and skips the root tests: a green dashboard/runtime log is not a green check.
- A static-markup test cannot exercise an error boundary (React's server renderer does not run them).
