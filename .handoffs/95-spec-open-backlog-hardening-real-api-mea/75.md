## Decisions & deviations
- Schema `pattern` is wider than the ticket's two refusals, for the same reason (the path is joined to `ctx.cwd`): it also refuses a leading backslash, a drive prefix (`C:`), `..` split on `\` as well as `/`, an empty string, and any line break (a path with a newline would add lines to the list in the prompt). A name that merely contains two dots (`docs/a..b.md`, `..hidden`) is accepted; a test pins both sides.
- `contextFiles: []` is valid and means no context block (tested). No `minItems`.
- The error text for a refused path is Ajv's `must match pattern "..."` at the pointer that names the key, the same shape as `repoHosts`; the schema description says what is refused.
- The instructions edit in `prompts.ts` (see Absorbed) changes the constant prefix of the plan and PR-text prompts, so a run resumed across this upgrade re-runs its memoised plan step. Acceptable: nothing else depends on the text.
- `.agents/workflows/config.json` carries a relative `$schema` (editor validation in the dogfood repo) and no `kit` range: a range would make the kit refuse itself on a version bump and nothing here needs it.
- Docs: the config reference shows the default list (generated, from the schema description). The setup skill's reference does not spell the default paths, because `test/repo-layout.test.ts` forbids a `docs/` path in a distributed skill; it points to `wf config show implement-issue`.
- No `CLAUDE.md` or `AGENTS.md` edited.

## Learnings
- A distributed skill's markdown may not contain a `docs/` or `scripts/` path even inside a code span (`test/repo-layout.test.ts` regex on `(^|[^\w/.-])(docs|scripts)/`): point at a command (`wf config show <workflow>`) instead.
- Running one runtime test file by hand needs `--tsconfig tsconfig.test.json` (the fake SDK): without it the file hangs on the real SDK until the timeout. From `packages/runtime`: `mise exec -- npx tsx --tsconfig tsconfig.test.json --test test/<file>`.
- Root tests (`test/*.test.ts`) run with plain `npx tsx --test`; a root test importing a runtime config helper typechecks under `tsc -p test`, so narrow `unknown` config fields before use.
