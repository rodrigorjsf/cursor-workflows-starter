## What was built
- The Board's `implement-issue` board has a **Backlog** column in front: the open issues of every repository in the runs index that carry the backlog label and have no run, each with a **run** button. A workflow with no run yet gets a board with that column alone.
- The label is the new `implement-issue` setting `backlogLabel` (`workflows.implement-issue.settings.backlogLabel`, default `ready-for-agent`, one label, no comma); schema, `docs/reference/config.md` and the setup skill's key list updated.
- The issues are read through the forge seam: `Forge.listIssues` (`gh issue list --state open --label=<l> --limit 100 --json number,title,url`; `glab issue list --label=<l> --per-page 100 --output json`), run by the new engine-free `readBacklog` (`workflows/implement-issue/backlog.ts`, exported through `observe` with `issuesWithRuns` and `BACKLOG_WORKFLOW`).
- `GET /api/backlog` (`{workflow, cards, errors}`) is its own read: the dashboard keeps each repository's forge answer (list or error) 60 s (`backlogCacheMs`), asks at most 4 repositories at once, and drops issues that have a run on every request. A forge/config error is an `errors` entry shown on the column; `/api/board` never waits for it.
- The run button opens the Start panel pre-filled (repository, `implement-issue`, `{"issue": n}`); the user gives the caps and the start is `POST /api/start`, so the required caps and refusals apply unchanged.
- Test fakes answer from recordings of the real tools: gh from `packages/runtime/test/fixtures/gh/recordings.json` (new, `scripts/verify/record-gh-fixtures.ts`), glab from `recordings.json` re-recorded on a real GitLab CE (`issue-list`, `issue-list-empty`; recorder seeds a third issue).

## Decisions & deviations
- **Backlog label = `implement-issue` setting**, not a new top-level config key: settings already layer global < repo file only, are schema-validated, and `wf gc` already sets the precedent of a setting read by another consumer.
- **Own endpoint, not part of `/api/board`**: the forge call waits (up to the network timeout), the Board must not; the page merges the two polls (`app/backlog-board.ts`). The column kind `backlog` was added to `ColumnKind` for the CSS class only.
- **Run button opens the pre-filled Start panel** instead of starting in one click: both caps are required (spec story 33) and the panel already shows the server's refusals.
- **"Has a run"** = an `implement-issue` run in that repo whose job record `start.args.issue` is that number (immediate, before the card exists), else, for a run with no job, the `#<n>` its card starts with. A `repo` arg that names another repository does not count; one that names this repository does (compared with the origin as `host/path`, case-insensitive, any CLI spelling). Known limitation: a no-job `wf run` on another repository's issue takes the same number off this Backlog (the card does not say which repository). Documented in 5.3.
- **No `origin` remote = nothing to list, no error** (a scratch repository is not a broken one); added after review.
- **At most 100 issues** (`ISSUE_LIST_LIMIT`), oldest number first, forge-independent sort in `readBacklog`; documented, not announced in the UI.
- **gh recording**: new `scripts/verify/record-gh-fixtures.ts` (read-only, real gh against the origin repo, `owner/repo` placeholder) because the standards require fakes to answer from recordings; docs table row, header, fixture test added. The real list is not sorted by number, which is why the Backlog sorts.
- **glab recording**: ran `scripts/verify/gitlab-e2e.sh` (`GITLAB_E2E_STAGES=references`, container `wf-gitlab-e2e-7`, port 18929, removed at the end, no tokens spent) after adding `listIssues` calls to `record-glab-fixtures.ts`; the whole `recordings.json` was rewritten (new timestamps), plus a third seeded issue.
- **Edited `CLAUDE.md`** (one sentence, two lines): the `observe` exception now also says it "asks that repo's forge for its ready issues (the Backlog)"; reason: CODING_STANDARDS "A behaviour change updates every text that describes it", raised by the Standards review.

## Learnings
- Recording a new glab command: add the call to `scripts/verify/record-glab-fixtures.ts`, then `GITLAB_E2E_NAME=<ticket-name> GITLAB_E2E_PORT=<free port> GITLAB_E2E_STAGES=references mise exec -- scripts/verify/gitlab-e2e.sh` (image already pulled; about 4 minutes, no tokens); it rewrites the whole `recordings.json`.
- A fake CLI script embedded in a template literal needs doubled backslashes (`\\n`, `\\/`, `\\d`): a Python/sed edit that writes a single one breaks the script silently until it runs.
- Real `gh issue list` is not ordered by issue number: sort in code, never assert an order from the recording.
- A test of "never more than N at once" needs a gate in the stand-in process (a file the fake waits on), not a sleep: assert after the Nth start, then release.
- `python str.replace(old, new, 1)` does nothing when `old` is absent: assert the old text is there when editing files from a script.
