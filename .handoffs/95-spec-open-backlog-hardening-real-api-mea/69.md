## Decisions & deviations
- **The registry premise was false.** The ticket says a module without `meta.name` "goes into `broken` today". It was skipped silently. I followed the ticket's intent: a default export that is present and not a workflow is `broken`; a module with no default export at all stays silent (a helper the workflows import, as `event-log.test.ts` has). This changes behaviour for repos with such files, so `loadWorkflows` (`wf run`, `wf list`, `wf doctor`) now stops on them. CHANGELOG says so. Three test fixtures were "workflows" without `run` (`init.process.test.ts`, `relocated-install.test.ts` x2) and were fixed.
- **The count in the ticket was out of date.** 17 of 24 casts at `d1ec1bf`; at `efb4340` there were about 37 `JSON.parse` sites, 30 with a cast, and the GitHub sites had moved from `implement-issue.ts` to `forge.ts` (ADR-0009). I converted every shipped one and allowlisted 7 (kit's own `package.json` x3, a bundled package's manifest, the shipped config schema, three recordings a script wrote). Reasons are in the test, keyed by file and argument text so a moved line does not break it, and a stale entry fails.
- **Guard vs zod.** Flat "peek at one field" sites (`mcp-launch`, `doctor`, `kit-version`, `retention`, `pr-by-url`, `savedSecrets`, two scripts) use `isRecord` and `typeof`; nested data (job record, lock, pid file, progress, memo, forge answers) uses zod. State-file schemas are `z.looseObject` so a newer kit's field survives; each is typed `z.ZodType<Interface>`.
- **Liveness readers return undefined, not an error** (job record, run lock, dashboard pid file): that is their documented contract for an unreadable file (a throw would break `listJobs` and the stale-lock takeover). A wrong shape now joins the not-JSON case. A record or lock with a field of another type is not a record: a lock with `pid` as text no longer counts as a live holder. `JobStart.args` became optional (JSON keeps no `undefined`, so a job started without args has none).
- **Memo and progress errors throw**, as a corrupt file already did (SyntaxError), now naming the file and field and ending with a remedy.
- **A GitHub `issue view --json` recording does not exist.** I checked the schema read-only against the real `gh` 2.102.0 on this repository's issues (`number` int, `title` and `body` strings, `labels[]` objects with `name`; `comments[].body` string) and used the recorded `issue list`. An issue with an empty body was not among the last 100 issues, so `body: null` is unobserved; GitHub's GraphQL `body` is a non-null string.
- **No-new-`!` for tests**: `assert.ok(x)` narrows; the tuple type of `whileActive` takes at least one case.
- `summary()` and `exportRows()` return `Record<SummaryTable, Row[]>` and `Record<ExportTable, Row[]>`, so the fixed keys are not `possibly undefined` for every caller.
- No `CLAUDE.md` or `AGENTS.md` edited.

## Learnings
- zod 4: a `z.unknown()` key is required at runtime ("expected nonoptional"): write `z.unknown().optional()` for a key that may be absent.
- `noUncheckedIndexedAccess` makes `marker?.[0] === fence[0]` stop narrowing `marker` (both can be undefined): test `marker !== undefined` first.
- A `Record<string, T>` return type hides fixed keys: use a literal union of keys so callers get no `possibly undefined`.
- A recorded-fixture test for `gh issue view --json` needs `scripts/verify/record-gh-fixtures.ts` extended; until then check shapes read-only with `gh issue view <n> --json ...`.
- Node 22.23 `ts.createProgram` over the root tsconfig takes about 4 s: a checker-based repo test is affordable.

## Notes for dependent tickets
- Reading JSON in `packages/*/src`, `packages/*/workflows`, `scripts`: use `parseJson(text, schema, source)`, `tryParseJson` or `isRecord` from `packages/runtime/src/runtime/parse-json.ts`; a new `JSON.parse(...) as T` fails `test/typescript-strictness.test.ts` unless allowlisted with a reason there. A new field on `JobRecord`, `LockContent`, `DashboardInstance`, `Progress` or `SliceRecord` also goes into its schema (`JOB_RECORD`, `LOCK_CONTENT`, `DASHBOARD_INSTANCE`, `PROGRESS`).
- A workflow file's default export needs `meta.name` and `run`, or it is `broken`.
- A new test project must resolve with the nine flags (it extends `packages/runtime/tsconfig.json`); a CSS import in a browser page resolves through `packages/dashboard/css-modules.d.ts`.
- An expression statement whose value is a promise needs `await`, `return`, `void` or `.catch`; an assignment holds it (`test/floating-promises.test.ts`).
- The dashboard job/lock readers now go through zod: the dashboard process loads `zod` through `observe`.
- Real-API budget: none spent. Network reads: `gh issue view` on this repository (read-only).
