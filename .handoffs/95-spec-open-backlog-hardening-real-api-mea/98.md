## What was built
- The Run view of an `implement-issue` run that stopped at `seams-proposed` (or `test-command-proposed`) shows a panel: the seams, the slices, and the test command approval lets the run execute, as text. Two buttons: **Approve** and **Replace seams** (a box, one seam per line; an empty list is refused inline). No reject.
- `POST /api/runs/<runId>/seams/approve` (body `{digest}`) resumes the run with its recorded args, caps and overrides plus `approveSeams: true`. `POST /api/runs/<runId>/seams/replace` (body `{seams}`) resumes it with `seams: [...]`. Both sit behind the same CSRF + origin `gate` as cancel and resume; both answer `202 {jobId, runId}`.
- A run that waits for no decision (not `implement-issue`, not at a proposal, or already resumed) is refused 409 by both actions. `GET /api/runs/<runId>` carries `seamsProposal` only for a run that waits.
- A run that no job started (`wf run` in a terminal, or a record with no `start`) shows its proposal with no buttons and a note to decide from the terminal; the server refuses it 409 with the same pointer.
- The audit comment on the issue is the workflow's own (#96); the dashboard posts nothing.

## Decisions & deviations
- **Where the plan is read:** the latest run-end result says that the run waits (and at which stop); the plan comes from the run's `tdd-progress.json` `proposedPlan` (read-only, `new ProgressStore`, narrowed through a zod `PLAN` schema, never cast). The `seams-proposed` result does not carry the test command, and approving executes the planner's command through `bash -c`, so the panel has to show it. The ticket allows "progress or events".
- **Approve carries a `digest`** (sha256 prefix of stop, seams, slices, effective test command). A stale page cannot approve a plan it never showed: mismatch is 409 "the proposal changed since this page showed it". Missing digest is 400. Replace sends no digest: it runs nothing the person did not write, and a `test-command-proposed` stop then shows the planner's command for its own decision. This is beyond the ticket's literal text; it is a security finding (listed under Absorbed).
- **Effective test command shown** = the `testCommand` typed when the run started (from the job record's args), else the planner's, else `npm test`: one rule, `testCommandOf`, moved with `Plan`/`Slice` to `workflows/implement-issue/plan.ts` and used by the workflow and the panel.
- **Args composition:** approve = recorded args without `seams`, plus `approveSeams: true` (the workflow's own relaunch line for `test-command-proposed` drops `seams`, or the planner would run again); replace = recorded args without `approveSeams`, plus `seams`. Caps and overrides repeat as recorded (as #97).
- **`launchResume`** (run-resume.ts) now holds the frozen/retention/no-start checks and the start for both the Resume button and the seams decision; `resumeRun` and `approveSeams`/`replaceSeams` call it.
- **Status codes:** 202 on success, 404 unknown run, 400 bad body, 409 for every state problem of an existing run (like #97).
- **No Backlog/other surface touched.** No ADR, no `CLAUDE.md`/`AGENTS.md` edit.
- **Browser smoke not done:** the `chrome-devtools` MCP server failed to connect in this session ("Connection closed"), so the wiring in `RunView.tsx`/`use-run-events.ts` was checked only through `tsc`, the esbuild bundle that every dashboard process test builds, and static markup of the panel (not in a real browser).
- Texts updated: `CHANGELOG.md`, book 5.3 (`docs/operating/03-observabilidade.md`: API table, new section "Decidir as seams de um run do implement-issue", Start section pointer, security list), `docs/authoring/01-escrevendo-workflows.md` (checkpoint step 3), `SECURITY.md`, `CODING_STANDARDS.md` (gated actions rule), `docs/contributing/01-contribuindo.md` (the dashboard line and the file map), `packages/dashboard/package.json` description, header comments of `server.ts`, `observe.ts`, `run-resume.ts`, `seams-approval.ts`.

## Learnings
- A repo-level `.agents/workflows/implement-issue.mjs` shadows the kit's workflow of the same name: a cheap real-job-process test for any dashboard action on `implement-issue` runs.
- A read-only step is memoised by its prompt: a runtime test that needs a second, different plan must change the issue text (`issue(labels, title)`), or it gets the first plan back.
- `run-view/` is typechecked with `types: []`: wire types are redeclared in `seams-form.ts`, and a guard narrows the untrusted JSON.
- `npm test | grep` reports grep's exit code: redirect `npm run check` to a file and print `$?`.
- The `chrome-devtools` MCP failed to connect ("Connection closed") this session: plan a browser smoke only when it is listed as connected.
