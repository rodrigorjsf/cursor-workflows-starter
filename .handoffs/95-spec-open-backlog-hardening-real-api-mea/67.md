## Decisions & deviations
- **`Agent.getUsage` is asserted too.** `packages/runtime/src/observability/queries.ts` calls `Agent.getUsage(id, { apiKey })`, which the ticket's list omits; the research error "Expected 1 arguments, but got 2" was this call.
- **Narrowed results.** The fake does not model `reload`, `summarize`, `model` of an agent or `supports`, `stream`, `conversation` of a run. The conformance cuts the real result to the members the runtime reads (`Using`, `UsedAgent`, `UsedRun`, `SentRun`), with parameters and the cut members taken from the real types. A member removed from the real SDK fails the alias.
- **`calls` and `script` stay `any`.** Typing `calls` as `AgentOptions[]` and `script`'s `o` as `AgentOptions` gave 101 errors in 9 test files (`o.cloud.repos` optional chains, 370 use sites) and no conformance gain: they are test-side controls, the SDK-facing signatures are what the conformance checks. Tried and reverted.
- **`tsc -p packages/runtime/tsconfig.test.json` (sources against the fake) is not added to `typecheck`.** After this change it no longer reports the three gaps the research named; what remains is the fake agent and run not modelling the whole interface (`reload`, `summarize`, `supports`...) and a `lib` too old for `Promise.withResolvers` in that config, which is only read by tsx. The conformance direction (fake fits real) is the ticket's decision.
- **Relative import path ends in `index.js`**, not `index.d.ts` as the ticket writes: `allowImportingTsExtensions` is off, so NodeNext resolves `index.js` to the `.d.ts`. Same file.
- **`export type *`** instead of an explicit list: no list to keep in step with what the sources import. Local `const`/`class` exports (`Agent`, `Cursor`, the errors) win over the re-exported type names.
- **Fake fidelity changes** that the typing forced or invited: `getRun` finds nothing unless `options.runtime === "cloud"` (the old fake required `{ agentId }`); the fake errors keep `code` and `status` from their options (real `CursorSdkError` does); `Cursor.models.list()` builds a fresh catalog per call.
- **Process test of `wf login`/`wf models` added** (not in the ticket): the two fake members need a consumer, and `wf login` carries the repo rule that `SdkLoginResult.apiKey` is never printed.
- **Stale text corrected in the paragraphs touched:** skills' testing reference said `npm run typecheck` does not cover the tests and to import the fake's controls from `@cursor/sdk`; `CODING_STANDARDS.md` said test files and helpers are not typechecked. All three were made untrue by PR #94 or by this change.
- No `CLAUDE.md` or `AGENTS.md` edited.

## Learnings
- `satisfies` against a real SDK type passes for the wrong reason when the fake's member resolves to `any` (a spread of an `any`, `new Promise(() => {})`): annotate the fake's return type, then mutate once and see the compile error.
- A conformance file in a test folder needs a canary that fails if a `paths` swap maps the SDK to the fake, or it compares the fake with itself.
- `export type * from "<relative path to the package d.ts>"` re-exports an SDK's types out of a fake that replaces the bare specifier through `paths`; `.js` in the path resolves to the `.d.ts`.
- `npm run check` outlasts a foreground call: start it once with `run_in_background`, no subshell, and wait for the notice.
