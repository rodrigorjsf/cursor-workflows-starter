## Decisions & deviations
1. **Schema is a character set; the host policy runs in `run`.** The ticket's regex `^(github\.com/)?[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$` predates GitLab (ADR-0009: `group/sub/project`, URLs, scp remotes are valid `repo` values) and the schema cannot read `repoHosts`. A refusal in `run` throws, so the run ends `failed` (exit 1, job `failed`), not `refused`, and the run directory exists. Not returned as a result status on purpose (CODING_STANDARDS "explicit status"): a security refusal must fail loudly, like invalid args. The review flagged this; dismissed, reason in the comment at `implement-issue.ts`.
2. **`forges` hosts and the origin host are allowed without `repoHosts`.** The user already declared or uses them; `repoHosts` covers the rest (and is the ticket's explicit allowlist). `repo: ""` is now refused by the schema (it used to mean "absent").
3. **`GIT_ALLOW_PROTOCOL=file:https:ssh` instead of a `git remote get-url --push` pre-check.** Git applies it to the URL it actually uses (push URL for push, fetch URL for ls-remote, after `insteadOf`/`pushInsteadOf`), and it overrides a user's `protocol.ext.allow`. `file` stays allowed: local bare remotes send no credential, the cloud snapshot check lets local paths through, and the whole suite pushes to local bare repos.
4. **Engine check at the start of `runWorkflow`**, not lazily before the first `Agent.create`: every later SDK call of the run (usage, cloud resume/listRuns) uses the same environment. A workflow that creates no agent is refused too.
5. **An empty endpoint variable counts as unset.** The SDK's `||` and `??` fallbacks make an empty value send nothing anywhere.
6. **GitLab four-segment paths** (`a/b/c/d`) are read as `HOST/...` (first segment is a host) and scheme-less three segments only when the first has a dot; GitHub reads any three as `HOST/OWNER/REPO` (checked against gh's parser by the Spec reviewer). The GitLab rule is a guess about `glab`: see #102. A URL with a scheme that does not parse is refused.
7. A URL `repo` with a scheme other than https/ssh (`http://github.com/o/r`, `git://`) is refused: the CLI would send the token in the clear.
8. No `CLAUDE.md` or `AGENTS.md` edited.

## Learnings
- `cmd > log &` inside a background Bash call returns at once and detaches the suite: use `run_in_background` on the bare command (`mise exec -- npm run check`).
- `spawnSync` blocks the event loop of a test that also hosts a listening socket: a "no connection" assertion after it reads 0 even when the child connected. Use async `spawn` and let pending accepts run (`setImmediate`) before reading the count.
- Git ignores `ext::` by default, but a user's `protocol.ext.allow=always` lifts that: only `GIT_ALLOW_PROTOCOL` makes the refusal hold. Git splits an `ext::` command at spaces and does not honour quotes (`ext::touch /path/without/spaces`).
- `test/forge-docs.test.ts` fails any doc block that names `gh` without `glab` in the same block.
- To split a mixed commit into red/green pairs: write the commits as a script in the scratchpad that runs `git checkout <final-sha> -- <paths>` per pair, then diff the tree against `<final-sha>`.
