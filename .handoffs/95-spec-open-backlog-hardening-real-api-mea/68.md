## Decisions & deviations
- **`--test-timeout=600000` in `packages/runtime`, not 120000.** node:test applies the timeout to each test *file* as a whole. With 120000, `doctor.process.test.ts` (165 s alone, 57 process tests) and `implement-issue.hardening.test.ts` (50 s alone, over 120 s under the full parallel run) failed with `failureType: 'testTimeoutFailure'`. "Raise the value per test" cannot help a whole file. 600000 is above the whole runtime suite (4m33 locally, CI job 4.5 to 6.5 min), so only a hang trips it, and it is far under GitHub's 360. Root (35 s whole suite) and dashboard (26 s) keep 120000. Splitting the slow files to keep 120000 was rejected: it fixes `doctor.process` only, and the margin of every process file under CI load stays thin.
- **github-actions gets only `cooldown.default-days: 7`.** The ticket writes `{ default-days: 7, semver-major-days: 14 }` for both ecosystems, but GitHub's Dependabot options reference (fetched 2026-11-14) says the `semver-*` cooldown keys are "Not supported" for github-actions. The acceptance criterion (`default-days >= 7`) holds for both; npm keeps `semver-major-days: 14`. A comment in `dependabot.yml` says why; the test asserts the npm major days only.
- **Matrix cadence comments in `ci.yml` and the owner step.** The matrix comment in `ci.yml` is English (new comments are English, review finding). Renaming or adding a matrix item changes the required-check names, which only the owner can change in the ruleset.
- **`engine-strict=true` and `CODING_STANDARDS.md`.** The Node-floor rule used to say npm does not enforce `engines`; it now says `engine-strict` refuses an install below the floor and the matrix still proves the code runs. Checked: no lockfile package needs more than Node 22.13 (script over `package-lock.json`), and `npm ci --ignore-scripts` with `engine-strict` succeeded on 22.13.0, 22.23.4 and 24.22.2.
- **The `uses:` rule is split across two test files** (owner in `coding-standards.test.ts`, pin in `supply-chain.test.ts`), each pointing at the other; the root test files are self-contained by convention, so no shared helper.
- No `CLAUDE.md` or `AGENTS.md` edited.
- Not verified: macOS (only Linux x64 was measured; SECURITY.md and book 2.1 say so), Node 26, and the mermaid job end to end. For the last one, `npm install --ignore-scripts --no-save --no-package-lock --prefix <dir> @mermaid-js/mermaid-cli@11.17.0 puppeteer@25.17.0` succeeded and put `mmdc` and `puppeteer` in `node_modules/.bin`, and `puppeteer browsers install chrome-headless-shell` ran but this sandbox could not download the browser ("All providers failed"). The CI `mermaid` job is the proof; that explicit step existed before the change.

## Learnings
- node:test applies `--test-timeout` to each test file as a whole: size it above the slowest file under a full parallel run, not above one test.
- Node 24: `node --test` defaults to the spec reporter off a TTY, and `module.builtinModules` lists `node:`-prefixed modules. Name `--test-reporter=tap` and filter `node:` entries.
- Dependabot cooldown `semver-*` keys are unsupported for github-actions; use `default-days` only.
- Fetching a runtime (a Node binary) with `npm install node@…` into the scratchpad is denied by the permission classifier here; list the Node line as unverified instead.
- `mise exec -- npm …` outside a repo with a `mise.toml` picks the broken Node 22.11 npm: use `mise exec node@22.23.4 -- npm`.
- A backgrounded foreground command (after 180 s) is still one run: do not start a second suite while it runs.
