## What was built
- A **Start** button in the dashboard's top bar opens a panel: repository, workflow, args (JSON box pre-filled with a skeleton of the workflow's required fields) and `maxTokens` / `maxCents`. A start that works opens the new run's Run view; the run then shows on the Board.
- `POST /api/start` (behind the same CSRF token + origin gate as cancel) starts the same detached job `wf start` starts. `GET /api/repos` and `GET /api/workflows?repo=` feed the form.
- The server resolves what may start: the repository must be in the global runs index (exact string match, folder still there), the workflow must be one the runtime lists for it, args are validated with the engine's Ajv check, both caps are required (> 0), the config caps still apply (`violations` in the 202 reply say what was cut).
- Refusals are `{ error }` with a sentence: 403 gate, 400 malformed body / missing or bad cap / args that fail the schema (field named), 404 unknown repository / unlisted workflow, 409 runtime refusal (inside a workflow step, kit outside the repo's range, unusable config). A refusal creates nothing in the repository.
- Runtime side: `startRun`, `knownRepos`, `listRepoWorkflows` (+ types, `errorText`) exported from `@cursor-workflows/runtime/observe`, in engine-free modules so the dashboard process still never loads `@cursor/sdk`.

## Decisions & deviations
- **Status codes:** success is `202`; refusals stay inside the documented set (400, 403, 404, 405, 409). Invalid args are 400, an unknown repository/workflow 404, a runtime refusal 409.
- **Caps must be a number greater than 0** (the ticket only says "required"): a cap of 0 starts a run that stops at once. A `null` or absent cap is "required"; text or non-finite is "must be a number".
- **Args must be a JSON object** (absent = `{}`), like the MCP tool's `args: { type: "object" }`.
- **Repository match is exact string equality** with an indexed `repo` and the folder must still exist; nothing is normalized, so `<known>/../other` is refused.
- **Skeleton:** only `required` fields, each a blank of its type (`""`, `0`, `false`, `[]`, `{}`) or the schema's `default`/`const`/first `enum`; optional fields are named under the box (`optionalArgs`). Blanks are deliberately values a schema with `minimum`/`minLength` refuses, so an unfilled field fails instead of running on a made-up value.
- **Gate before the body:** `startDashboard.gate` (shared with cancel) answers 403 before the body is read; body limit 256 KiB (400).
- **Workflow listing imports the repo's workflow files into the dashboard process**, as the MCP server does for its repo; documented in 5.3 and SECURITY.md. Files are imported again when changed (`discoverWorkflows(cwd, { fresh: true })`, URL carries mtime+size).
- **Engine-free split (needed so the dashboard never loads `@cursor/sdk`):** `createJob`/`spawnJob` moved from `jobs.ts` to the new `job-spawn.ts` (`jobs.ts` re-exports them: many importers); `newRunId` moved to `state.ts`; `INSIDE_WORKFLOW_ENV` to the new `inside-workflow.ts` (CLI and MCP server import it from there; the engine's re-export was dropped); the args check to the new `args-schema.ts` (`argsError`), now used by the engine too.
- **`cancelRun` (Run view) now goes through the shared `postAction`** in `app/dashboard-api.ts` (same texts and statuses as before); the Start panel uses it too, so a CSRF-token dance exists once.
- **Edited `CLAUDE.md` (one sentence, wrapped to two lines):** the `observe` exception now says it also "starts one in a repo the index names". Reason: CODING_STANDARDS "A behaviour change updates every text that describes it" — the old sentence (reads logs, cancels jobs) would be untrue. No other lines touched.

## Learnings
- A job spawned by the dashboard inherits the dashboard's `process.execArgv`: launch the dashboard with the `tsx` bin (absolute loader paths); a bare `node --import tsx` makes the job fail with `Cannot find package 'tsx'` in a repo without node_modules.
- When the `chrome-devtools` MCP is down, headless `~/.cache/ms-playwright/chromium-1248/chrome-linux64/chrome --headless=new --no-sandbox --remote-debugging-port=<p>` plus Node 22's global `WebSocket` is enough to drive the dashboard over CDP.
- Importing `engine.ts` (or `jobs.ts`) loads `@cursor/sdk`; anything reachable from `observe.ts` must stay engine-free (`job-state`, `job-spawn`, `run-start`, `args-schema`, `inside-workflow`).
- The gitleaks pre-commit hook flags a 40-hex SHA after `Base:` in a handoff (`generic-api-key`, redacted output): write short SHAs there, and use `gitleaks git --staged --redact -v` to see the rule.
- `path.join` normalizes `..`: build a non-normalized path with a template string when a test must prove an exact-match check.
