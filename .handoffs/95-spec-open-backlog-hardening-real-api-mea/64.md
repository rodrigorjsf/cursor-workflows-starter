## What was built
- `wf upgrade` and `scripts/install.sh --tag` (over an existing clone) stop with `the kit at <kit> has local changes: <list>; reinstall it` when the installed kit's tree is not clean, before they fetch, check out or run `npm ci`. The kit stays on its tag. `wf upgrade` checks even when the kit is already on the newest tag.
- "Not clean" is `git status --porcelain --untracked-files=all --ignored=matching`, minus the kit's own `node_modules/`. The list prints git's codes (`M path`, `?? path`, `!! path`).
- `wf doctor` has a tenth check, `kit` (last in the order). A tag install must have a clean tree and HEAD exactly on `v<its package version>`. A dev install (a link) is reported as such and not checked. No kit at the path passes ("nothing to check"); a kit folder that is not a git clone fails.
- Docs: new section "Reinstalar o kit" in `docs/usage/01-instalacao.md` (what the list means, `mv` the kit aside, run the installer again, what the check does not see), the `kit` row in the doctor table (2.3), SECURITY.md, INSTALL-AGENT.md, the setup skill, both READMEs, the 9.4 script table, the file map, and two CHANGELOG entries.

## Decisions & deviations
- **Absorbed beyond the ticket's command:** the ticket says `git status --porcelain --untracked-files=all`. I measured in a scratch repo that this hides an `.npmrc` listed in `.git/info/exclude` and any file under a folder with its own `.gitignore` of `*`; `--ignored=matching` shows both and collapses `node_modules/` to one line (`--ignored` without `=matching` plus `--untracked-files=all` lists every file under `node_modules/`). The check therefore also counts ignored files, minus `^!! (.*/)?node_modules/$`. Cost: any ignored file in an installed kit (`.env`, `*.db`, `.workflows/`) now makes the kit "dirty"; none exists in a clean install (the dashboard cache and metrics live under `~/.cursor-workflows`, not in the kit).
- **Check before the fetch, also at the newest tag** (`upgrade.ts` right after `installedKit()`): an edited kit is reported even when there is nothing to upgrade. The installer checks first thing in the existing-clone branch, before `remote set-url`.
- **`git tag --points-at HEAD` includes `v<version>`** instead of `git describe --exact-match --tags HEAD` equals `v<version>`: with two tags on one commit, `describe` prints one and can fail a good kit.
- **Doctor details:** `kit` is appended last (ids and order of the nine others unchanged); the kit checked is `<WF_HOME>/kit` and its version is read from that kit's own `packages/runtime/package.json`, not from the `wf` that runs the doctor (a dev `wf` with an installed tag kit would otherwise fail); a missing kit passes, a kit folder with no `.git` fails (checked with `existsSync` so a parent repository, a dotfiles repo say, is never read by mistake).
- **`install.sh --refresh` is not checked.** It is how a freshly checked-out tree is finished (`wf upgrade` checks before the checkout), and two existing tests edit the kit on purpose to simulate a new tag. A hand-run `--refresh` on a dirty tag kit still runs `npm ci`; `wf doctor` reports that kit. Stated in the CHANGELOG entry.
- **Residual limit, documented, not fixed:** `git status` does not see `.git/` (hooks, config) or the contents of `node_modules/` (rebuilt by `npm ci` on every reinstall). Said in 2.1 `Reinstalar o kit` and SECURITY.md. The owner decided on a git-status check; a stronger one (hash manifest, read-only kit) is a different design.
- **Existing test changed:** "wf upgrade whose checkout fails …" edited `package.json` to make the checkout fail; that now trips the new check first, so it plants `.git/index.lock` instead (clean tree, git cannot take the lock).
- **Test infrastructure:** the fake `npm` now creates a real `node_modules/` folder of links (the kit's `.gitignore` pattern `node_modules/` does not match a symlink, so the old single link showed as untracked); `.gitignore` joined `KIT_PATHS` of the test origin so the real ignore rules apply.
- `upgrade.ts` lost its private `git` and `messageOf` helpers: `kitGit` (kit-state.ts) and `errorText` replace them.
- No `CLAUDE.md` or `AGENTS.md` edited.

## Learnings
- `git status --porcelain --untracked-files=all` does not list a file named in `.git/info/exclude`, nor files under a folder whose own `.gitignore` says `*`; add `--ignored=matching` (collapses ignored folders; plain `--ignored` expands `node_modules/` file by file).
- A `.gitignore` pattern `node_modules/` does not match a symlink named `node_modules`: a test that fakes `npm ci` must make a real folder or the clone looks dirty.
- A `.git/index.lock` in a clone makes `git checkout` fail while `git status` still works: a way to fail a checkout on a clean tree in a test.
- The doctor's check count sits in five places of `doctor.process.test.ts` (title, id list, `All good: N`, `x of N`, `checks.length`): grep `checks.length` too when adding a check.
- A foreground `npm run check` is moved to the background after 180 s: run it in the background redirecting to a file with `echo EXIT=$?`, then wait with `Monitor` on that marker (a `sleep` in Bash is blocked).
