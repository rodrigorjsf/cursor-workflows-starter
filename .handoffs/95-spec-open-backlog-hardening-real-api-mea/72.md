## What was built
Run state is private to its user, and the journal and memo no longer live forever.
- **Private modes.** `.workflows/` and every folder in it is created `0700`, every state file `0600` (event log, journal, run lock, memo, job record, job log, the record of a `ctx.exec` process group, the heartbeat worker's rewrite of the job record), whatever the umask. `worktrees/` is not touched. Nothing is `chmod`ed: a folder or log that exists keeps its mode.
- **Installer.** `scripts/install.sh` runs `umask 077` first thing in `main`, so `~/.cursor-workflows/` and its config are born `0700`/`0600`.
- **`wf doctor`.** A new eleventh check, `state` (last in the list), warns (never fails) when `.workflows/` is reachable by group or others, names the mode and gives `chmod 700 <folder>`. It passes when the folder is private or absent and creates nothing.
- **Retention.** For runs outside the retention, pruning also removes `result` from every journal line (the line stays with key, label, model, costs and `pruned: true`). A pruned run is refused on resume with `run <id> cannot be resumed: the retention policy deleted the step results its journal held…`, before any step and without writing to its log. Memo entries older than `days` are deleted.

## Decisions & deviations
- **`writeFileAtomic(file, data, mode = PRIVATE_FILE)`** is private by default; `wf init` passes `0o666` for repo files (it shares the function; AGENTS.md and the MCP configs must not become 0600). A whole-file atomic rewrite creates a new file, so a rewritten state file (job record, pruned log) takes the new `0600`: the mode only tightens. The ticket says "existing files are not changed silently": nothing is `chmod`ed, a folder or log that exists keeps its mode (pinned by "a folder or a file that exists keeps its mode"), and the docs say a rewritten-whole file is a new one.
- **New doctor check id `state`** (the 11th, appended so the order of the first ten does not move). 70's handoff rode the `config` check to avoid a new id; here a dedicated check is clearer and the cost was the count in tests and three docs. On Windows it passes ("no Unix modes"). Group or others having any bit (`& 0o077`) warns, not only read: execute lets a known file name be read. The hint says the `chmod` does not stick on WSL `/mnt/c`.
- **Journal marker is `pruned: true` on every valid journal line** (even one that had no `result`), `Journal.pruned` is true if any line has it, and `RunStore` throws `RunPrunedError` (caught in the engine into the existing `refused` outcome, like `RunLockedError`). A run with no journal line (it failed in its first step) has nothing to lose: it is not marked and resumes from the start.
- **Memo ages by the file's modification time**: a hit does not refresh it. Only `days` applies; a `null` `days` keeps every entry; the `runs` limit does not touch the memo (it belongs to the repo, not to a run). `MemoStore.get` now treats `ENOENT` as a miss (retention in another process may delete the entry between the check and the read; the old `existsSync` then `readFileSync` would have thrown).
- **Renames**: `pruneContent` -> `pruneRuns`, `RunStore.pruneOldContent` -> `pruneOldRuns` (they prune more than content now); no other caller.
- **Left alone on purpose**: `dashboard-instance.ts` log and lock files and the runs index live under `userDir()`, which is already `0700` (the runs index goes through `appendJsonl`, so it is `0600` now anyway); `worktree-snapshot.ts` writes under `worktrees/` (excluded); the implement-issue PR body file is in an `mkdtemp` folder (already `0700`).
- No `CLAUDE.md` or `AGENTS.md` edited.

## Learnings
- `process.umask(0o022)` in a test is inherited by the children it spawns (`wf start`, the installer): no `sh -c umask` wrapper needed; restore it in `after`.
- A heartbeat worker rewrites the job record on its own thread: a test that looks at the record's mode sets `WF_HEARTBEAT_MS` small and waits (with `waitFor`) until the heartbeat moves on.
- `writeFileAtomic` is private (`0600`) by default now: a caller that writes repo files must pass a mode (`wf init` passes `0o666`).
- `npm run check` takes about 4 minutes: start it with `run_in_background` and wait for the notification.
- A Python edit of the form `open(p, "w").write(open(p).read())` truncates the file before it reads it: write the text in a variable first.

## Notes for dependent tickets
- A run outside the retention cannot be resumed: `runWorkflow` returns `{ status: "failed", refused: true, error: "run <id> cannot be resumed: ..." }`, so a job started to resume it ends with `refused` set on its record (`jobs.ts`). The dashboard resume ticket should expect that message for old runs (a failed run's `run-end` still carries the old `resumeHint`).
- `state-files.ts` exports `PRIVATE_FILE` (0600) and `PRIVATE_DIR` (0700); any new place that creates run state under `.workflows/` passes them (`stateDir`, `writeFileAtomic` and `appendJsonl` already do).
- `pruneRuns`/`pruneMemo` are in `retention.ts`; `Journal.pruned`, `withoutResults` in `journal.ts`; `RunPrunedError` in `run-store.ts`. `RunOptions.retention` governs the memo too (only `days`).
- `wf doctor` has eleven checks, `state` last: a ticket that lists the checks (docs, skills, tests) must include it.
