## Learnings
- Under the sandbox with no `.cursor/sandbox.json`, an agent step reaches no host at all, not even `registry.npmjs.org` (`curl: (6) Could not resolve host`, `npm` `EAI_AGAIN` after about 70 s); the SDK points the npm cache and logs to `/tmp/cursor-sandbox-cache/<hash>/npm/`, and a write to `~/.cache` is `Permission denied`.
- `git add`, `git commit` and `git log` work in a git worktree under the sandbox even though `.git/worktrees/<name>` is outside `cwd`.
- The agent runs shell calls in parallel: a `git add` and a `git commit` in the same batch race (`nothing to commit`).
- The SDK writes a `terminals/<pid>.txt` per backgrounded shell command under `~/.cursor/projects/<repo>/`: the only place a long-running command's full output lives; `events.jsonl` keeps just the exit line.
- A step's log (`step-start`) does not say whether the step was sandboxed: proof needs a step that prints `CURSOR_SANDBOX_*`. Logging the flag on `step-start` would make a run self-proving (an event-schema change, so left out of this ticket).
- The broken login-profile `npm` of this machine (`~/.local/bin/npm` → mise 22.11, missing `npm-cli.js`) still makes an agent's `npm test` fail with or without the sandbox.
- A grep over a long run directory also matches the clone's own name when it contains the word `sandbox`: name scratch clones without it, or filter by event type.
