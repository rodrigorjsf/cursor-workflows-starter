## What was built
- `wf init [--no-agents-md | --remove] [--cwd <repo>]` writes the kit's files into the target repo, prints a unified diff of everything it changed on stdout
  (empty when nothing changed; the summary and notes go to stderr), and never runs git: no commit, nothing staged.
- `.cursor/mcp.json`: the `workflows` server at `${userHome}/.cursor-workflows/kit/...` with `WF_CWD=${workspaceFolder}` and no `WF_MAX_*`.
  `.mcp.json` (Claude Code): the same server through `${HOME}`. Both were started as the IDEs start them (variables substituted, command run in the repo)
  and answered `tools/list` and `list_workflows` with the repo's own workflow.
- `.agents/workflows/config.json` with `$schema` (raw.githubusercontent.com URL) and `kit` (`>=0.2.0 <0.3.0` for kit 0.2.x; major line from 1.0); `.gitignore` gets
  `.workflows/`; `AGENTS.md` gets a 4-line block between the begin/end markers (rules + pointer to `INSTALL-AGENT.md`), file created if missing.
- Idempotent: a second run prints nothing and changes nothing; a file that already says what init would write is not rewritten, whatever its formatting.
  `--remove` takes only the `AGENTS.md` block out (the file goes if the block was all it held); `--no-agents-md` skips the file.
- Everything is planned before anything is written: a config file that is not JSON, or a begin marker without an end marker, fails the command with the file named and
  leaves the repo untouched. Writes are atomic and go through symlinks (an `AGENTS.md` -> `CLAUDE.md` link stays a link).

## Decisions & deviations
- **Kit location fixed at `${userHome}/.cursor-workflows/kit`** (spec: "per-user location under `~/.cursor-workflows/`"; #19's AC names `~/.cursor-workflows/kit`). Until #19 installs there, the generated server does not start; docs 2.3 says so.
- **`.mcp.json` uses `${HOME}`** (Claude Code expands `${VAR}` in command/args/env); no `WF_CWD` there, like the dogfood `.mcp.json`: Claude Code starts the server in the project root.
- **`$schema` = raw URL on `main`** (`raw.githubusercontent.com/.../main/packages/runtime/schema/config.schema.json`). The `blob/` URL #14 put in the schema's example returns HTML, which an editor cannot read; I changed that example to the raw URL (regenerated `docs/reference/config.md`). `$id` still holds the blob URL (an identifier, never fetched). `main` and not `v<version>`: the tag of an unreleased version does not exist, and v0.2.0 has no schema.
- **Pointer in the `AGENTS.md` block = `.../blob/main/INSTALL-AGENT.md`**, static text in `templates/agents-md-block.md` (no templating): a tag in the URL would rewrite the committed block on every kit upgrade. The file does not exist yet (#19 creates it at the repo root); the link dangles until then.
- **Block squeezed to 4 lines** (the ticket says 3–4): the API-key and nested-workflow rules share a line, plus the pointer. The existing `repo-layout` assertions on the block still hold.
- **Kit range**: minor line below 1.0 (`>=0.M.0 <0.(M+1).0`), major line from 1.0, prerelease ignored; derived from `packages/runtime/package.json`. Existing `kit`/`$schema` in a repo config are kept, only missing ones are added in front.
- **Existing `workflows` MCP entry**: `command`/`args` are rewritten, `env` gets `WF_CWD` merged in, other keys/servers stay. A `WF_MAX_*` the user already had in that env is kept (env is a config layer under the global caps, ADR-0001, so it cannot loosen anything); not stripping a user's setting silently.
- **`--remove` undoes only the `AGENTS.md` block** (user story 7: "cleanly undo the `AGENTS.md` block"); `--remove --no-agents-md` is a usage error.
- **Unified diff written in-house** (`unified-diff.ts`, ~60 lines, LCS after trimming the common head/tail, 3 lines of context) rather than shelling out to git: stdout is deterministic and needs no git config. Checked once against `patch` as an oracle: 400 random before/after pairs, every generated diff applied to the "before" gave "after" (scratch script, not committed).
- Runtime messages pt-BR, code comments English, template and `AGENTS.md` block English (repo convention).
- **TDD honesty**: slice 1 (MCP configs), slice 2 (repo config) and the AGENTS.md slice went red -> green one at a time, and the diff/missing-cwd tests went red before `unified-diff.ts`. The `.gitignore`-already-ignored, idempotence, "keeps other servers", invalid-JSON and no-commit tests were written after the code they exercise existed, so they passed on first run; I mutation-checked them instead (no WF_CWD, range branches swapped, gitignore always appends, files always rewritten, block appended instead of replaced, write inside the plan loop, diff context 1, symlink replaced, remove keeps the blank line, template read from the checkout): each mutation failed at least one test. The first idempotence test missed "config.json always rewritten"; it now covers all three JSON files.
