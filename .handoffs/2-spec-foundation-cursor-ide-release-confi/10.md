## What was built
- The docs are a navigable pt-BR book. `docs/README.md` is the index: entry points per profile (user, workflow author,
  maintainer), then nine fixed parts (vision, usage, internals, writing workflows, operating, reference, ADRs, research,
  contributing) with every chapter in reading order. Parts 1, 6 and 7 say "Em preparação" (ticket #11 and later ones fill them).
- The nine chapters moved into `docs/usage/`, `internals/`, `authoring/`, `operating/` and are numbered `parte.posição`
  (the old "04" is 2.3, "03" is 3.1, ...). The two research reports (still in `docs/research/`, names unchanged) became 8.1 and 8.2.
  Every chapter ends with a previous/next footer. Dated measurements and `[DOC]` citations are untouched; only paths,
  cross-reference labels and H1 numbers changed.
- `scripts/check-docs.ts` (`npm run docs:check`, run by `npm test`) fails on a broken relative link or anchor, a chapter
  missing from the index, an index label not numbered `parte.posição`, an H1 that differs from its index label, and a wrong or
  missing footer (it prints the expected footer). `scripts/check-mermaid.ts` (`npm run docs:mermaid`) renders every Mermaid
  block in a new `mermaid` CI job and fails with `file:line` on a render error.
- `docs/contributing/` (part 9): 9.1 Contribuindo (the old CONTRIBUTING.md, plus the self-contained-skills rule), 9.2 book conventions,
  9.3 diagram conventions (theme-neutral `classDef`, no animation, `stateDiagram-v2`), 9.4 maintainer scripts table.
  Root `CONTRIBUTING.md` is now a short pointer. `.claude/rules/diagrams.md` (paths `**/*.md`) points at 9.3.
- Every script in `scripts/` carries a WHAT/WHY/WHEN/HOW header.

## Decisions & deviations
- **Numbering `parte.posição`** with part numbers fixed by the spec's order (1 vision … 9 contributing). Chose it over keeping 01–09 because the vision chapters (#11) come first in reading order and would otherwise force a renumber of every chapter and cross-reference. Cross-references and H1s were rewritten (`02 §3` → `2.2 §3`); the plain-text `docs 0N` pointers in `verificacoes-locais.md` too. CHANGELOG entries of 0.2.0 that name `docs/04`, `docs/08` are history and were left.
- **Index shows all nine parts**; empty ones say "Em preparação". Parts are `### Parte N · …` headings under `## Partes e capítulos`; chapter entries are `- [N.M · Title](path): description`; H1 must equal the label (a check beyond the four the ticket names, because numbers drift first).
- **Research reports keep their file names** (many files cite them by name); only the H1 got `8.1 ·` / `8.2 ·`. Code-path references inside them were updated to `packages/runtime/...`; verbatim command output (`node_modules/.bin/tsx src/mcp-server.ts - Pending approval`) and sandbox-repo paths (`src/math.js`) were left as recorded.
- **CONTRIBUTING.md moved into the book** (9.1) and left as a pointer at the root (GitHub shows it; `CLAUDE.md` names it). `scripts/verify/README.md` and the 8.2 report link straight to the chapter.
- **`README.md`**: the docs table became a per-profile pointer list (the descriptions now live in the index) and the tree names the new scripts; #11 rebuilds the hub.
- **CLAUDE.md/AGENTS.md not edited** (run rule). Still true through the pointer, but stale wording remains: `CLAUDE.md:5` "(`CONTRIBUTING.md` until the book lands)" and `CLAUDE.md:53` "Full policy in `CONTRIBUTING.md`". Suggested edit for whoever may touch it: point both at `docs/contributing/` (policy: `docs/contributing/01-contribuindo.md`), and add that `npm test` also runs the docs check.
- **Mermaid job not verified on a real runner.** mermaid-cli hangs locally per the spec, and in this sandbox the Chromium download did not complete (`Could not find chrome-headless-shell`). What was verified instead: the driver with a stub renderer, and all five repo blocks (including the two examples in 9.3) parsed with mermaid 11.17.2's own parser under jsdom (a harness in the scratchpad that also rejects two deliberately broken diagrams). The job pins `@mermaid-js/mermaid-cli@11.17.0` (released 2026-09-02) and runs a `--version` warm-up outside the per-block time limit so a cold download is not billed to the first block. Watch this job on the final PR.
- Footer rule: blank line, `---`, blank line, footer line (a rule glued to text would render as a heading).
- Link/anchor checking covers every Markdown file in the repo (not only `docs/`), skipping symlinks, `node_modules`, `.handoffs`, run state. Indented code blocks (4 spaces) are still scanned for links: telling them from list continuations needs a full CommonMark parser, and the failure is loud and fixable with a fence.

## Learnings
- `npx @mermaid-js/mermaid-cli` needs Chromium that this sandbox could not download; check diagrams offline with `mermaid.parse` plus `jsdom` globals (`window`, `document`, `navigator`).
- When rewriting Markdown links by script, mask inline code spans with tokens first: splitting the line at code spans breaks links whose text contains a code span.
- `git checkout -- <file>` on an untracked file silently does nothing: back up before a mutation check on a new file.
- `gh issue view` printed nothing through the Bash tool here; `gh issue view N --json title,body > file` then Read worked.
- Two fixtures in the same temp tree need distinct files per test; `mise exec node@22.23.4 --` for every npm/tsx call.
