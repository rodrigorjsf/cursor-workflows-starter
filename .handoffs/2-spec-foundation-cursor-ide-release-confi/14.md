## What was built
- Behaviour is configured in two JSON files validated by one shipped JSON Schema (`packages/runtime/schema/config.schema.json`, draft-07, Ajv): the global
  `~/.cursor-workflows/config.json` (`WF_HOME` moves the dir) and the repo `.agents/workflows/config.json`. An invalid file, an unknown key or a
  misspelled role fails the run (and `start_workflow`, and `wf start`) before any step, naming the file and the JSON-pointer field path.
- Precedence: code defaults < global < repo < env (`WF_MAX_TOKENS`, `WF_MAX_CENTS`, `WF_MODEL_*`) < flag < `start_workflow` overrides. The global `caps`
  (tokens, tokens per step, cents, allowed models / setting sources / locations, max concurrency) then clamp everything: numbers take the minimum, lists
  intersect. A request above a cap is reduced to it and recorded as a violation; `null` disables a limit, an absent key inherits.
- Workflows declare roles in `meta.roles` (`name`, `cloud`, `defaults`, `envAliases`); `implement-issue` declares its eight. Config sets model (with
  params, merged field by field), timeout, retries, schema retries, per-step token cap and setting sources per role, with label globs as the fallback for
  steps without a role. The engine applies the layers to each `agent({ role })` call.
- `start_workflow` takes `overrides` that can only tighten (a looser one comes back in `violations` and has no effect). The config is read afresh at every
  run start (also a resume) and at every `start_workflow`.
- `run-start` records `config` (effective), `provenance` (per JSON pointer: layer + file/env var/flag) and `violations`; `step-start` records `role`.
  `wf config show [workflow]` prints the three plus the two file paths.
- `docs/reference/config.md` (book chapter 6.2) is generated from the schema (`npm run docs:config`); `npm test` fails when it drifts.

## Decisions & deviations
- **`caps` in the repo file** (spec: "caps (global only)"): accepted by the schema (one schema for both files) but reported as a violation and ignored; the repo tightens through preferences, which the caps clamp.
- **Clamp semantics**: an over-cap request becomes the cap (`min`), as the spec's "numbers take the minimum" says, not "fall back to the layer below". `null` under a finite cap is a violation (effective = cap). Code defaults above a cap are clamped silently (provenance `cap`).
- **Tighten-only is relative to the resolved value** (cap included), not just to the cap; applies to `start_workflow.overrides` only. Flags (CLI / embedders) are trusted: they may loosen the repo but never the global cap. A chat `maxTokensPerStep` is a ceiling for every role and label cap too (review finding).
- **Number validation** is one rule for env, flags and chat overrides (`limitProblem`): tokens and per-step caps integers >= 0, cents >= 0, concurrency integer >= 1; anything else is a `ConfigError` naming the source. Before, `WF_MAX_*` that did not parse were ignored silently.
- **Model merge is field by field** (`id`, `params`, `maxMode`): `WF_MODEL_X=id` or a layer's `model: { id }` keeps the params of the layer below ("keep model params"); `id[k=v,max]` / explicit `params` replace; `id[]` clears. This can carry a model's params onto a different model; documented in 6.2 and 2.2, `id[]` is the way out.
- **Role defaults live in `meta.roles[].defaults`**; precedence inside the code layer: `defaults` < role defaults < the call's own options; config layers beat all. `fix` and `design` declare no model (it depends on tier / step), so the call sites keep their code defaults. `design` covers the planner (MED), the three designers and the judge (HIGH). Behaviour change: `WF_MODEL_MED` / `WF_MODEL_HIGH` no longer move the fix and design steps (they are their own roles); in CHANGELOG and 2.2.
- **Env mapping**: `WF_MODEL_<ROLE>` = role name upper-cased, `.`/`-` -> `_`, plus `envAliases` (`LOW`, `MED`, `HIGH` kept for `implement.*`). A `WF_MODEL_*` that matches no role of the workflow is ignored (env is shared by all workflows); unknown roles in files / `agent({ role })` are errors.
- **`cloud` capability values** (spec leaves them open): `classify` ok; `review`, `design`, `pr-text` read-only; `implement.*`, `fix` never (write to the local worktree).
- **Types of the recorded config live in `events.ts`** (pt-BR docs, like the rest of the file) so the events page documents them; the config module imports them. New runtime messages pt-BR, new comments English.
- **Schema descriptions are pt-BR** (they are the text of the generated pt-BR reference and the editor tooltips). Field paths are JSON Pointers (`/workflows/implement-issue/roles/review/retries`), unambiguous because role names contain dots.
- **Violation of the code default**: a role's default model that `allowedModels` refuses is reported as a violation with layer `default` at run start (its steps fail at `agent()` with a clear message); a spec-review finding.
- **Violations are also emitted as `warning` events** after `run-start`, so they show in the job's `recent` lines.
- **Out by design**: `maxTokensPerStep` is configured, clamped and recorded, but enforced live by #15; the `kit` version range is validated as a string only (#18 refuses a mismatched kit); retention config is #13; workflow-specific preferences (slice caps…) are #26.
- **TDD honesty**: slice 1 (schema validation) and the review fixes went red -> green. For the remaining slices the resolver was written in one pass and the tests followed; I then mutation-checked them (final-clamp off, layer order swapped, tighten allowed to loosen, role-name check off, overrides ignored in the engine, model replaced wholesale, cap violation off, source clamp off, model allowlist off, concurrency from opts, glob order, env alias off, no ceiling propagation, no limit validation, no default-model violation, schema not copied to a relocated install): each mutation failed at least one test.

## Learnings
- A fresh worktree has no `node_modules`: the root `npm test` needs `ln -s <main>/node_modules <worktree>/node_modules` (untracked; remove it before the final `status --porcelain`, `.gitignore`'s `node_modules/` does not match a symlink).
- A test whose scripted step hangs (`{ hang: true }`) turns a regression into a 30-minute wait (default step timeout): give it a `{ timeout }`.
- `pkill -f <test file>` from the agent's own shell can kill that shell; stop a background command with the task tool and restore mutated files by copy.
- tsx does not typecheck: run `npm run typecheck` separately after every edit round.
