## Decisions & deviations
- **Approach 1 of the brief** (guarantee both runs exist) for the existing test, not approach 2 (weaken to "cancels equals returned sends"): it keeps the stronger assertion `cancels === 2` and `spentTokens === 500`, and the race it covers now has its own test.
- **The gate is signalled by `send()` having been called, not by the engine binding the run.** That is deterministic because everything between the fake's `send()` return and `attemptCut.bind(run)` (`engine.ts` `send` wrapper, `within`'s `Promise.race`) is microtasks, and the first delta needs `await gate` plus a `setImmediate` macrotask. Both reviewers' reading of the event loop agrees. If the engine ever put a macrotask (timer, I/O await) on that path, the test would need a different signal.
- **My first version of the cut-before-send test was itself racy** (stress run 1, iteration 1: `1 !== 2` on `calls.length`): under load, `a`'s turns could cross the cap before `b`'s step had even called `Agent.create`, which is another path (a step refused at its start, `assertBudget`). Fix: `a`'s first turn is gated until `b` is inside `createGate`. Caught only because the 50x loop under load was run before declaring done.
- The two variants share one helper, `runCapCrossedByTwoSteps({ delayBCreationMs })`; the delayed variant also asserts that the delay really applied (guards against a silent no-op if the agent-name format `<workflow>:<label>` changes).
- The unused `events` array of the run-cap test was dropped.
- No `CHANGELOG.md` entry: test-only, nothing user-visible.

## Learnings
- The main checkout's `node_modules` may lag the lockfile (here `semver` and `@types/semver`, added by #17/#18, were missing, so `npm run typecheck` failed with TS2307 in `doctor.ts` and `kit-version.ts`). In a worktree, build `node_modules/` as a real directory of symlinks to the main checkout's entries and add the missing packages as real copies (`npm pack <pkg>@<version>` into the scratchpad, extract, copy); `@types/` must also be a real directory, or the copy would land in the main checkout.
- A stress loop under load (one busy loop per core) found a race in a test that passed 10 isolated runs: run it before calling a timing-dependent test deterministic.
- `gh issue view` prints nothing through the shell wrapper unless asked for `--json` or redirected to a file.

## Notes for dependent tickets
- Fake SDK additions for any live-cap or cancellation test: `gate` (live script entry), `costConfig.createGate(options)`, `stats.sends`. To make parallel live steps deterministic, push `holdUntilAllSent(plan)` (local to `live-caps.test.ts`) once per step; to hold one step's creation, use `createGate` keyed on `options.name.endsWith(":<label>")`.
- Engine behaviour confirmed by the new test (no change needed): a step cut while `Agent.create` is pending throws its budget error right after the agent is created, never sends, and its late agent is disposed.
