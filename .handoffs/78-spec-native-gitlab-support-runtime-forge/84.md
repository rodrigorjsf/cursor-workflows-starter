## What was built
- `neutralizeGitlabText` in `packages/runtime/workflows/implement-issue/forge.ts`, called by `sanitizeModelText` (`pr-body.ts`), the one door every piece of model text takes into an MR/PR body and the seams comment. A line that starts with a known GitLab quick action (`/close`, `/merge`, ... any case, 100+ names from GitLab's "Quick actions" page plus legacy names) is shown as code (`` `/close` ``); `!12`, `~label`, `%milestone` get a zero-width space after the sigil. A path (`/usr/bin/env`), a lone `/tmp` and text inside a three-backtick fence stay as written. The body's own `Closes #N` / `Refs #N` line is never passed through the sanitizer, so it is kept.

It redacts from logs and events and blocks a delivery (the outbound guard shares the list), like the GitHub tokens.
- Absorbed (see below): the closing-keyword filter now also covers GitLab's `Closing/Fixing/Resolving/Implement*`, `issue #N`, subgroup paths and issue URLs.

## Decisions & deviations
- One sanitizer for both forges (not forge-conditional): the spec says "the existing sanitizer ... also neutralizes". On GitHub a `/close` line only gets backticks; the hardening tests run on both forges.
- Shown as inline code for quick actions (robust: the line no longer starts with `/` whatever GitLab normalizes), zero-width space for references (same device `sanitizeModelText` already uses for `@mentions`; a backtick wrap would break a model's own code span).
- Where it lives: `neutralizeGitlabText` is in `forge.ts` ("the GitHub and GitLab differences in one internal module", as #81 did with `prLabel`); `pr-body.ts` imports it. Header comment of `forge.ts` mentions it.
- Fence trust. GitLab decides what a fence protects over the whole description. I read `lib/gitlab/quick_actions/extractor.rb` (master, 2026-11-13): the current extractor takes paragraphs from a Markdown pipeline (CommonMark) and also excludes inline code and HTML blocks; older versions matched a regex. So a fence is trusted only in the form both agree on (three backticks at column 0, info without backtick, bare three-backtick closer); everything else fence-like (indented, tildes, four or more backticks, trailing-space closers) gets a leading zero-width space and protects nothing. Trust is off for the whole piece when a line starts an HTML block, a quote (`>`, `>>>`) or `$$` outside a fence (they can swallow a fence's opener). An open fence is closed, and a fence on the first or last line gets a line break, so a piece cannot leave a fence open for the next piece to close (which would put that piece's code outside a fence) nor join a prefix/suffix on the same line. `\r` is removed (GitLab does it before matching). Cost: a model's tilde or list-nested fenced code shows a zero-width space on its fence lines.
- The quick-action name list is the docs page (18.x) plus legacy names; `cc` is left out on purpose (a no-op since 15.0, removed in 18.3, and the extractor skips no-ops). A name GitLab adds later is not known until the list is updated; the test "every quick action of GitLab's documentation is known" holds the documented set.
- CHANGELOG: no entry here; #90 owns the release entry (same call as #81).
- Skills: the two byte-identical `references/rules.md` copies got one word (GitLab in the credential list) by direct edit, not through `/mattpocock-skills:writing-for-agents` (a list item, not skill writing); they stay byte-identical.
- No `CLAUDE.md` / `AGENTS.md` edit.
