## What was built
- Config key `forges` (host, lower case, optional `:port` -> `github` | `gitlab`) in both config files and the JSON Schema. It layers code < global < repo **host by host** (a host only the global file names stays; the repo file wins on a host both name). No env var, flag or chat override reaches it, and no cap clamps it. `config.forges` and `provenance["/forges/<host>"]` are in the effective config, so `run-start` and `wf config show` carry them. Workflows read the map as `ctx.forges`.
- `detectForge(commands, cwd, forges, repo?)` in `workflows/implement-issue/forge.ts`: the host of a `repo` argument that is a URL decides the forge; otherwise the host of `origin`. `github.com` / `gitlab.com` are known (any port); any other host is looked up in `forges` (`host:port` first when the URL has a port, then the bare host); an unknown, undeclared host throws before the lock and before any step, with an error naming the host and `"forges"` and showing the declaration to add.
- Nested groups: `group/sub/project` (and URL / scp-like spellings of it) work as the `repo` argument, in the REST routes (one encoded segment), in the run lock and in the same-repository check (proved by tests, case-insensitive; the same path on another host or port is another repository).
- `glab api` gets `--hostname <host[:port]>` when the `repo` argument is a URL naming a host.

## Decisions & deviations
- **Merge per host, not whole-map replace.** `settings` replace whole; for `forges` a user declares a self-managed host once in the global file and another in a repo, so per-host merge is the only reading that makes both stories (7 and 8) work together. Provenance is per host.
- **Port matching.** Key `host:port` is tried first when the URL has a port, then the bare host, so a key without a port matches any port (an ssh remote's port is not the web port). `github.com`/`gitlab.com` are known on any port.
- **Keys are lower-case hosts** (schema pattern); no normalisation, so two spellings cannot collide.
- **A `forges` entry that gives `github.com` or `gitlab.com` (with or without a port) the other forge is a `ConfigError`** ("remove the entry"), because detection would ignore it silently. Repeating the known forge is accepted and kept in `config.forges`.
- **The `repo` argument names a host only through a URL** (`https://`, `http://`, `ssh://`, scp-like `git@host:path`). `HOST/owner/repo` is not read as a host: `group/sub/project` cannot be told apart from it (a dotted top-level group), and glab's support for the form is unverified. It fails loudly at the CLI, never silently. `--repo` is passed to the CLI as given.
- **A host-less origin stays GitHub** (local path, drive path `C:/…`, no `origin`): no host exists to name, and "a GitHub user sees no change" (story 12); `gh` reports the missing remote itself. A drive path is not read as scp-like `host:path` (guard in `parseRemote`).
- **`ctx.forges` on the public `WorkflowContext`** (readonly copy, like `ctx.settings`): the only way the built-in workflow receives the config map. It is data, not the seam (`ctx.forge` stays out of scope, ADR-0009). Documented as one row in both copies of `runtime-api.md`; dismissed as scope creep in review for that reason.
- **Docs touched** because tests or CODING_STANDARDS force them: schema descriptions (pt-BR, they feed the book), regenerated `docs/reference/config.md` and `events.md`, a `forges` bullet in `scripts/config-reference.ts`, the setup skill's key list, `ctx.forges` rows, a new Configuration rule in `CODING_STANDARDS.md` and its re-pointed `_See:_` lines (checked one by one). Book prose, README, install and authoring chapters stay with #87; no CHANGELOG (#90); ADR-0009 unchanged (it already says "`forges` map" and "unknown host is an error"; the port and per-host-merge details live in the schema description).
