# Handoff — #91: backend.local send-grace test fails intermittently under the full suite: it bounds elapsed time with Date.now()

## What was built
Every test that bounds elapsed time or sets a wait deadline now reads the monotonic `performance.now()` instead of the wall-clock `Date.now()`. That removes the WSL2 clock-resync cause of the intermittent "send() never hands back a run" failure (`packages/runtime/test/backend.local.test.ts:189-193`), and the same hazard in 17 other test files and helpers (`wait-for.ts`, `support.ts`, the `until` helpers, process tests).
A new convention check in `test/coding-standards.test.ts` keeps it that way: any `Date.now()` in a test folder that is not building a timestamp (`new Date(Date.now() - ms)`) and has no `// wall-clock-ok: <reason>` on its line fails the root suite. `CODING_STANDARDS.md` lists the check on the Testing "Enforced by tooling" line.
No product code changed.

## Decisions & deviations
- Chose ticket option 1 (monotonic clock) as the ticket says to run first. Margin of the bound in the named test is unchanged (1250 ms); a later failure now points at CPU contention, not a clock jump.
- Converted deadline loops too (`Date.now() + ms` / `Date.now() > stop`), not only `x - startedAt` bounds: a forward clock jump fires a deadline early the same way. The ticket's "any other test that bounds elapsed time" covers it.
- Added the convention check and the `CODING_STANDARDS.md` clause. The ticket's criterion 1 is a grep a person runs once; the check makes it hold on later commits. Repo convention (CODING_STANDARDS "Enforce a repo convention with a node:test that reads the files").
- The ticket's grep pattern missed three elapsed-time bounds that still used `Date.now()` (backend.cloud.test.ts:377, dashboard.process.test.ts:185, exec.process.test.ts:98) and every deadline loop; the check found them and they are converted.
- Kept wall clock, with `// wall-clock-ok:` markers, where the test compares with or hands over a wall-clock timestamp: event-log.test.ts:305/317 (compared with `startedAt` the run wrote), fake-sdk.ts:177 (`createdAt` as the real SDK reports it), cloud.lifecycle.test.ts:554 (heartbeat timestamp the job record is read against).
- Marker shape copies `fixed-wait-ok:` (same-line `// wall-clock-ok: <reason>`, reason of at least 5 characters).
- Did not touch the out-of-scope `&&` chaining in the root `npm test`.
- No `CHANGELOG` entry: test-only change, no behaviour a user sees.
- `mise trust mise.toml` was run once in the worktree (writes to mise's user-level trust state, not to the repo); `mise exec` refused an untrusted `mise.toml`.

## Learnings
- `mise exec` in a fresh worktree fails with "Config files ... are not trusted": run `mise trust mise.toml` there before `mise exec -- npm ci --prefer-offline`.
- A ticket's acceptance grep can undercount: write the convention check first and let it list the real offenders.

## Notes for dependent tickets
- Time bounds and deadlines in tests: use `performance.now()`. A `Date.now()` is allowed only inside `new Date(...)` or on a line ending `// wall-clock-ok: <reason>`; the root suite fails otherwise (`test/coding-standards.test.ts`).
- `waitFor` (`packages/runtime/test/wait-for.ts`) now measures its deadline on the monotonic clock; its API is unchanged.
- New tests for the forge seam (fake `glab`, gc, doctor) that wait or bound time inherit the rule.
