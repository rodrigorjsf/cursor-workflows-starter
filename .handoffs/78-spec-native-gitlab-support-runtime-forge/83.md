## What was built
- `wf gc` on a GitLab repository is covered end to end by process tests against the fake `glab`: the four MR states (`opened`, `locked`, `merged`, `closed`), the recorded forge surviving a moved `origin`, a record with no forge read as GitHub, the latest MR of a branch, "no MR" (empty list) versus an auth error.
- The production path for runs (`createForge(forgeNameOf(progress), …)` and `GitlabForge.prState` with `opened`/`locked` as `OPEN`) already existed from #81; this ticket proves it. Those tests were green on first run, so red was shown by mutation (below), not by a failing first run.
- One production fix, absorbed (found while writing the tests): `wf/` branches on the origin that no run of the repo owns were always asked to `gh`. On a GitLab repository `gh` fails, so any foreign `wf/` branch made `wf gc` exit 1 and the branch could never be cleaned. They are now judged by the forge of the origin's host (`detectForge`, looked up once, when the first such branch is met). Shared legacy `wf/issue-<n>` branches stay GitHub (they belong to runs from before the forge field).

## Decisions & deviations
- Unowned origin branches use `detectForge(commands, cwd)` (the origin's host as it is now), lazily. ADR-0009 says gc "never detects again"; that rule is about runs, which have a record. A branch no run owns has none, and the branch is enumerated from the origin as it is now, so the origin's forge is the consistent one. Recorded as a dated `**Amended:**` line in ADR-0009 (the repo's rule for a clarification that keeps the decision), and in the `gc.ts` header comment.
- Config leg of the first criterion: the `forges` key does not exist yet (#82), and gc reads no config for a run's forge, so a config change cannot reach it. Only the remote leg is tested. #82 should add the config leg to the "gc asks the forge the run recorded…" test (declare or undeclare a host in the config after the run, then gc) when it adds the key.
- `setPrState` mixes the kit's states with the raw `"locked"`: kept in one function, documented, because the fake glab prints any other raw state as is and the GitHub tests never pass `"locked"`.
- A new test file instead of converting the old one: `implement-issue.gc.process.test.ts` uses top-level `beforeEach(setup)`, which would double the set-up for `forgeTest`-registered tests. The helpers moved to a fixture instead. `forgeTest` of the new file runs the tests that name GitLab's states on gitlab only; the two "origin moved" tests run on both forges.
- No docs edit beyond the ADR line: the book's gc text (`docs/operating/01-governanca-e-custos.md`) does not name the forge and stays true; the docs for GitLab are spec B (#87).
