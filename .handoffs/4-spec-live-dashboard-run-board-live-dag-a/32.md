## What was built
- **Step log panel.** In the Run view (`/runs/<runId>`), clicking a node (or Enter on it, Esc to close) opens a panel beside the graph with the step's content, structured: per attempt the prompt (a re-prompt is its own block), what the agent said, each tool call with its arguments and the output under it (an MCP tool is titled `mcp: <tool>`); for a `ctx.exec` command, `$ command args`, the directory and the output with stdout and stderr apart. It follows the step live (content read once, then `events?stepId=…&lastEventId=…`), sticks to the tail until the reader scrolls up, and shows text removed by retention or cut at 32 KB as such. Everything is text, never HTML.
- **Cancel.** The header has `Cancel run` for a running run (inline confirmation). It is `POST /api/runs/<runId>/cancel`, the dashboard's only write route, which needs the CSRF token (`GET /api/csrf`, one random value per process, `X-CSRF-Token`), refuses a foreign `Origin` or a cross-site `Sec-Fetch-Site`, and ends in `cancelJob`, the function `wf cancel` calls (SIGTERM, or SIGKILL for a job whose heartbeat stopped). The card moves to Cancelled when the log records the end.
- **Copy resume command.** On a failed or cancelled run: `wf start <workflow> --args '<args>' --resume <runId> --cwd <repo>` to the clipboard, also shown in a text field. The log keeps only a hash of the args, so unless the args were empty (hash of `{}`, as for `smoke`: the command is then complete) the command carries a placeholder that is not JSON and the CLI refuses it unedited.
- **Navigation.** Board cards and Runs rows link to the Run view (this was missing from #30/#31).
- **Wizard scenario 7**, "the dashboard shows the run live" (a `smoke` run watched in Cursor's built-in browser: the card moving Ping to Done, the graph, hover, the step log). The release criterion now needs seven passes.
- Docs (book chapters 2.3 and 5.3, scripts, validate skill reference) and CHANGELOG updated.

## Decisions & deviations
- **Cancel finds the job by run id.** `readJob`, `listJobs` and `cancelJob` live in `jobs.ts`, which imports the engine (and with it the Cursor SDK; a dashboard test guards that the dashboard never loads it). The engine-free half moved verbatim to the new `packages/runtime/src/runtime/job-state.ts`; `jobs.ts` re-exports it, so the CLI, the MCP server and the runtime tests import as before. `observe` exports `cancelRun(runId, timeoutMs)` (`run-cancel.ts`): the run must be `running`, then `runningJobOf(repo, runId)` picks the job of the run whose process is still there (a resume is a new job over the same run), then `cancelJob`.
- **A run started with `wf run` in a terminal (no job record) is not cancelled from the dashboard**: 409 with "press Ctrl-C in that terminal". There is no record of its process to signal; guessing a pid from the lock would not be `wf cancel`'s path.
- **The cancel request waits up to 20 s** (what `cancel_workflow` waits; option `cancelTimeoutMs`) and answers 200 with `{jobId, runId, status, note}`; `status: "running"` plus a note means the job is still stopping.
- **CSRF**: the token is read from `GET /api/csrf` at each cancel (so a dashboard restarted since the page loaded still accepts it). Defence in depth: custom header (needs a preflight the server never answers), foreign `Origin` and cross-site `Sec-Fetch-Site` refused, the Host check first, constant-time comparison. No cookies exist, so there is nothing for a cross-site request to ride on.
- **The resume command is not fully "exact" for non-empty args** because the foundation spec stores only `argsHash` in the event log on purpose; storing args would be a design change (privacy) beyond this ticket. Hence the non-JSON placeholder (fails loudly, never resumes with other args), the exact form for empty args (the engine's hash of `{}`, pinned by a contract test), and a hint to repeat `--max-cents`/`--max-tokens` (also not in the log). Reviewer (Spec) raised this; the placeholder trade-off was judged reasonable, the empty-args case was absorbed.
- **Replay and the log panel**: the panel shows the content up to the log line of the last replayed event (`ids` now come with the events). The replay steps over the events that change the graph, so a step's log appears in full when the step ends in the replay; the slider can stop at every event. Not "typing out" the log.
- **Navigation links** (Board card title, Runs row id) were not in the ticket; the browser checks need them and #31 flagged them for the shell. Link helper `runHref` lives in `ui/format.ts` (the shell must not import across bundles); a test pins that it agrees with `runIdOf`.
- **`nodesFocusable={false}`** on the canvas: the node's own element is the control (role button, Enter/Space), React Flow's wrapper no longer adds a second tab stop.
- **Re-framing**: the canvas also re-frames when its pane resizes (the panel opening beside it), unless the user moved the view.
- **UI language** English, as #30/#31; docs and CHANGELOG in pt-BR, as the book.
- The Windows-Chrome check ran against the worktree's dashboard on `127.0.0.1:4332` with a throwaway `WF_HOME`, a real `smoke` run (22,114 tokens, 0 cents) and a repo workflow `slow` made of `ctx.exec` commands (cancel needs a run that lasts). Cursor's built-in browser was not available: that is wizard scenario 7.

## Learnings
- Verify every scripted multi-line replacement landed: use `assert old in s` in the Python edit; one silent miss shipped a dead feature that only the browser showed.
- A `child.once("exit")` registered after the child already died never fires: check `exitCode !== null || signalCode !== null` first, or the test hangs forever (use `timeout 100` on test commands you run by hand).
- The scratchpad directory is shared by the tickets of a session: `demo/` already held other tickets' runs; use a fresh `demo<ticket>/` folder for a clean Board.
- The dashboard builds its web app once, at start: restart the demo dashboard after every UI edit (a wrapper `.mts` with `setsid nohup`, port from `WF_DASH_PORT`), and reload the page, or you test the old bundle.
- `gh issue view <n> --comments` printed nothing through RTK here; `gh issue view <n> --json title,body,comments` to a file worked.
- Chrome-devtools uids go stale when the page re-renders (the Board polls): click through `evaluate_script` (`el.click()`), or take a fresh snapshot right before `click`. `navigator.clipboard.readText()` hangs on a permission prompt: do not call it.
- To make a run you can cancel without spending quota: a repo workflow (`.agents/workflows/x.ts`, a plain `export default {meta, run}`) that calls `ctx.exec("bash", ["-c", "… sleep …"])`, started with `wf start` (a real detached job).
