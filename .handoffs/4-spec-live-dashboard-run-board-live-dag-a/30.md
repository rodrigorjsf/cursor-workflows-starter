## What was built
- The dashboard's page (`/`) is one React app with three menus: **Runs** (every run of every repo, newest first), **Board** and **Metrics** (the old metrics panels, ported to React, same Portuguese text, same API). The menu is the URL hash (`#/runs`, `#/board`, `#/metrics`; no hash opens the Board).
- The app is bundled with esbuild when the dashboard starts (cold 53 ms, 235 KB of JS; cached 1 ms), cached by content hash in `<WF_HOME>/dashboard-cache/<hash>/`, and served by the dashboard itself as `/assets/app.<hash>.js|css` under `default-src 'self'; script-src 'self'; style-src 'self'` (no inline code, no remote origin).
- **Board** (`GET /api/board`): one kanban per workflow (newest run's workflow first). Columns are the workflow's phases, then Awaiting approval, Done, Failed, Cancelled. A card moves by itself as the run's log grows (the app polls every 2 s). Each card shows what the workflow set, plus repo, cost and duration from the run.
- **`ctx.card({title, subtitle?, links?, badges?})`** emits a new `card` event; the projection keeps the latest card per run (any execution). `implement-issue` puts its card up after triage (`#<n> <title>`, tier badge) and updates it on delivery (branch as subtitle, PR link).
- A card link to a `github.com` pull request carries its state (`open|merged|closed`): the server asks `gh pr view <url> --json state --jq .state` in the background (4 at a time), caches the answer (30 s open, 1 h settled, 5 min failure), and never makes the Board wait for it.
- `run-start` now lists the workflow's declared `phases`; `GET /api/runs` carries `phases`, `outcome` and `card` per run.

## Decisions & deviations
- **Columns come from the declared phases, carried by `run-start.phases`.** The dashboard cannot load workflow modules (it must never load the Cursor SDK, a test guards that), so the workflow's `meta.phases` is written into the log by the engine (optional field, no schema bump, older logs fall back to the phases the run entered). Phases a run entered but did not declare get their own column after the declared ones; a workflow with none has one `Running` column; a running run's current phase always has a column.
- **One board per workflow**, stacked on the page, newest run's workflow first. The ticket says "the workflow's phases", so columns differ per workflow; a single mixed board would collide phase names.
- **Placement**: running → its phase (first column before any phase); `finished` with outcome `pending` (`seams-proposed`, `pending`) → Awaiting approval; `finished` classed `failed` → Failed; `finished` classed `delivered` or `unknown` (a result with no status) → Done; `failed` (error, cap, or the process died) → Failed; `cancelled` → Cancelled; `missing` (log unreadable) runs are left off the Board (the Runs menu shows them with the reason). `outcome` reuses `outcomeClass`, so `wf gc`, the metrics DB and the Board agree.
- **Cost on the card comes from the run's projection, for every card**, not from `ctx.card`: it is live, and a badge written at emission time would go stale.
- **Polling, not SSE, for the Board** (2 s). The server only re-reads a run's log when its size or mtime changed (`projectLog` in `run-view.ts`, stamp = size + `Math.round(mtimeMs)`), which was the note from #28 (0.5-0.9 s per poll for 200 runs of 3 MB). Cost per poll is now one `stat` per listed run.
- **A card is read defensively**: only `http:`/`https:` links, wrong-typed items dropped, a card with no title is skipped (the one before it stays), text bounded (title/subtitle 200, label 80, URL 2048, badge 40, ≤8 links, ≤8 badges). A phase title is bounded to 80 and a run lists ≤30 phases.
- **PR lookups are a background queue, never awaited** (an uncached first Board load with 200 PR links would otherwise take about a minute). Cost: the first answer has a link without a state, the next poll has it. Only the exact `https://github.com/<o>/<r>/pull/<n>` goes to `gh`, as a fixed argument list.
- **UI language**: menu and Board strings in English as the ticket names them; the migrated Metrics text keeps its Portuguese and is marked `lang="pt-BR"`. Not translated: moved, not rewritten.
- **`metrics-page.ts` is deleted** (replaced by `ui/MetricsView.tsx`); `docs/img/dashboard.png` stays and is captioned as the Metrics panel.
- **Dependencies**: `react`, `react-dom`, `esbuild` added to `packages/dashboard` (esbuild was already in the tree through tsx); `@types/react*` as dev. The runtime gains none. `test/repo-layout.test.ts` ("the dashboard is its own workspace package") asserted the dashboard had no dependency but the runtime: it now asserts the exact set and that the runtime carries none of the three.
- `typecheck` now also runs `tsc -p packages/dashboard/ui` (DOM lib, JSX), in the root script and in the dashboard package.
- Not done, by scope: no `favicon.ico` file (a `data:,` icon link avoids the 404); no Run view or DAG (#31); no cancel/CSRF (#32).

## Learnings
- The chrome-devtools MCP's "selected page" is global to the browser, shared by every agent in a parallel wave: `navigate_page` hit another agent's tab once. Open your own tab with `new_page` + `isolatedContext: "<ticket>"`, check the `[selected]` line of the response, and close it afterwards. If you clobber a tab, navigate it back.
- `take_screenshot` with `filePath` is refused outside the Windows workspace roots: omit `filePath` and the image comes back inline.
- A detached `node … packages/dashboard/src/main.ts` of mine died twice while other agents ran their cleanups: start a demo dashboard through a wrapper `.mts` (`await import(".../main.ts")`) with `setsid nohup`, so its command line does not match `pkill -f dashboard`.
- `pkill -f '<pattern>'` also matches the shell that runs it when the pattern is in its own command line: `pgrep -f "[x]yz" | xargs -r kill`.
- `Stats.mtime` is `Math.round(mtimeMs)`: a cache stamp built from `trunc` or from the float cannot be restored with `utimesSync(date)` and made a test flaky 1 time in 2.
- Test logs can hold a NUL byte (a test prints `%00`): `grep` calls the file binary and prints nothing. Use `grep -a` on `npm test` output.
- esbuild resolves `react` from the importing file's directory: a copy of `ui/` outside the workspace needs `nodePaths` (done in `app-bundle.ts`).

- **Wire types**: the UI imports types only (`import type`) from `../src/board.js` (`BoardResponse`, `Board`, `BoardCard`, `BoardLink`) and from `@cursor-workflows/runtime/observe` (`RunSummary`). `RunSummary` gained `phases`, `outcome` (`OutcomeClass`) and `card` (`RunCard`); `run.phase` is bounded to 80 chars.
- **Bundle**: `buildApp({srcDir?, cacheDir?})` in `src/app-bundle.ts`; `startDashboard` awaits it, so a source that does not build stops the dashboard from starting. The cache hash covers every file under `ui/` plus the versions of `react`, `react-dom` and esbuild: **when #31 adds `@xyflow/react` and `elkjs`, add them to the package list in `contentHash`** or a version bump alone will not rebuild. Add them to `packages/dashboard/package.json` and to the expected set in `test/repo-layout.test.ts`.
- **CSP** is `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. Style set through React's `style` prop is allowed (CSSOM), `<style>` elements and style attributes in markup are not. A Web Worker falls back to `script-src 'self'`: elkjs must be its non-worker bundle (`elk.bundled.js`) or its worker served from this origin. CSS imported from a package (`@xyflow/react/dist/style.css`) is bundled into `app.css` by esbuild.
- **Server**: `GET /api/board?limit=` (route in `route()` of `src/server.ts`, inherits the Host and method checks); the assets are looked up in a `Map` before the `/api/runs/...` match. `startDashboard({port, prStateCacheMs?})`. `PrStates` (`src/pr-state.ts`) is closed by `close()`.
- **Runtime**: `WorkflowContext.card(card: WorkflowCard)`; `CardEvent`/`CardLink` in `events.ts` (docs page regenerated with `npm run docs:events`; add any new event type to the list in `test/events-reference.test.ts`); `RunStartEvent.phases?`; `latestCard`, `runPhases`, `boundedPhase` in `projection.ts`; `dashboardCacheDir()` exported by `observe`. A new `ctx` method also needs both copies of `skills/*/references/runtime-api.md` (kept identical by a test).
- **Board polling** costs one `stat` per listed run; `projectLog` (`run-view.ts`) re-projects only when size or mtime changed, so SSE for the Board is no longer needed for cost reasons.
- **Fixtures**: `fakeGh(box)` in `test/support.ts` for anything that shells out to `gh`; `writeRun(..., {phases})` writes the declared phases into the `run-start`.
